              概览

              没有这一节，改看概览。

              • GeniStudio 是一个流程驱动的自动化软件生产工场。
              • 适合有成熟流程和交付件模板的规模化开发，不适合单次或不确定性、探索性软件开发。
              • 可定制化程度高，包括但不限于角色、流程编排、运行时 Skill/MCP 配置、Agent 后端配置等。
              • GeniStudio 把人的交付目标交给项目所绑定的流程。
              • 流程由活动和决策点组成。活动按角色写出文档或代码，决策点停下来等人批复。
              • 工厂仓库和待开发项目分开。项目只选定流程、模型和通知，不在页面上另设一套场景。
              • 它适合已经有明确流程和模板、需要 Agent 长时间运行的工作。不适合单次、小型任务。
              • 安装步骤写在仓库的 README，完整说明在 docs/install.md。装好后打开这个 Web 页面。
              • 在「配置」的 Agent 里选择后端。想先熟悉界面，选 stub，它不调用外部模型。
              • 要让角色真正工作时，后端选 cursor 并写入 Cursor API Key，或选 codex 并使用本机 Codex 登录。密钥只保存，页面不回显。
              • 默认模型是每一轮里角色没有另选模型时使用的模型。留空则用该后端自己的默认模型。写完后按「写入 .env」。
              • 工作区可以先空着。项目里填写了工作区时用项目的目录；都没填时，才用配置页的默认工作区。
              • 飞书可以以后再配。需要通知和在飞书里批复时，再填写飞书后端、Web 地址，以及默认通知群或通知人。
              • 先准备流程。可以选内置的通用软件开发或自我改进，也可以先在「流程」里新建或复制。
              • 再新建项目并选定该流程。只写标题，标识会按标题生成。选择项目类型，并填写待开发项目的工作区。
              • 然后到「运行」。选定项目，填写交付目标，确认名称后启动。
              • 遇到决策点时，在待办里批准或驳回。批准后继续，驳回则这一轮结束。
              • 可以新建、打开，或从本机的 git 目录创建。
              • 新建只写标题。标识按标题生成，中文标题会译成英文。
              • 打开之后标识只读，再改标题也不会改标识。
              • 从目录打开时，标识按目录名生成，工作区就是这个目录。
              • 项目里可以选择项目类型、设计轨、节点裁剪、通知对象、工作区和流程。本地仓库的初始化与拉取由用户自行完成。
              • 项目必须选定一份流程。没有流程时，先去创建。
              • 先选择项目，再填写交付目标并启动。
              • 名称默认是项目标识加递增序号，启动前可以改。
              • 中栏是这一轮的泳道，只列出当轮会走到的节点。
              • 可以进行中暂停、继续或停止。
              • 决策点、需求澄清和回退升级停在待办里，批复后继续。
              • 点一个格子，右栏查看这一步的产物和该角色的会话。
              • 可以新建、编辑或导入一份流程。新建只写标题，标识按标题生成。编辑时选中一份就载入，选择框保持可用。导入读取 workflow.yaml，内置标记不会带入。
              • 载入非内置流程后，可以在复制和保存旁边删除。删除前要确认。内置流程不能删除。
              • 宽屏用泳道排列活动和决策点。右栏左缘可以拖动，改变右栏宽度。
              • 活动要写出输入和输出。每项输出要有模板。
              • 模板是服务进程能读取的本地文件，或一个 http、https 链接。
              • 决策点目前的决定类型是批准或驳回。
              • 把这份流程选进项目后，下一轮按这些节点执行。
              • 活动没有输出，或某项输出没有模板时，不能启动。
              • 左栏「角色」放在「流程」下面、「配置」上面。可以新建、打开、修改和删除。
              • 新建只写标题。标识按标题生成，中文标题会译成英文。打开之后标识只读。
              • 打开后可以改标题、类别、职责、原则与价值观、输入、输出和能力。
              • 输入和输出从工厂已有的产物名里选择。人类关卡不在这个列表里。
              • 已被流程使用的角色不能删除。先从那些流程里去掉，再删角色。
              • 泳道和流程里显示的是文件头里的标题。
              • 合规管理负责隐私、网络安全和知识产权，不代替 QA 的交付结论。
              • 新建活动时，用该角色文件中的输入和输出名字作为初值。
              • 模板仍要在流程页补上。
              • 在「配置」的 Agent 中选择后端。
              • stub 不调用外部模型。
              • cursor 使用 Cursor SDK，并复用该工作区里已有的工具、规则和 Skill。
              • codex 使用 Codex SDK，在目标工作区里读写文件并执行命令。
              • 默认模型是每一轮里角色没有另选模型时使用的模型。留空则用该后端自己的默认模型。
              • API Key 只有一个输入框，文字随后端变化。只写入本机配置，页面不回显。stub 不需要填写。
              • 默认工作区在项目没有填写工作区时使用。
              • 一轮任务在待开发项目自己的目录里进行，不改工厂仓库里的源码。
              • 项目里填写的工作区优先于这里的默认值。
              • 飞书用来通知和批复，和网页上的待办是同一套决定。
              • 可以填写飞书后端、卡片里使用的 Web 地址、默认通知群和默认通知人。
              • 项目里另外填写的通知群或通知人优先于这些默认值。
              • 配置页右栏的环境按 Agent、工作区、飞书分组。每一项左侧是名称，右侧是是否已配置。
              • 有具体取值时写在名称下面。密钥只显示已配置，不写出原文。
              • 飞书命令行单独列出安装、配置和发消息，说明按条目写在下面。
