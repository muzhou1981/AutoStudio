# auto_studio 需求

## 1. 原始需求

1. 这是一个自动化的 AI 软件工厂，接收人类输入的需求，产出经过验证的软件。
2. 包含不同角色的 Agent 定义，包括项目经理、架构师、程序员、测试工程师、QA。每个角色有各自的原则和价值观；基础版本由人工先行定义。
3. 有多套工作流程定义，每个角色在工作流程约束下工作，可针对不同场景选择不同流程。工作流程通过 LangGraph 编排；默认流程的第一版由人工编写。
4. Agent 后端支持插件机制，默认使用 Cursor SDK，后续支持 OpenAI SDK 等其他 Agent SDK。
5. 工厂支持自我进化：每一轮任务完成后，对模板、各个角色的输出以及流程自身进行复盘，以打分方式总结出 Top3 有价值的点和 Top3 需要改进的点。
6. 工厂自身的开发基于 Cursor IDE 进行，原始需求、项目计划等上下文信息在本目录自包含。
7. 包括文档和代码等所有的输出产物都需要有模板或规范，模板和规范也需要有默认版本以及可替换机制。

## 2. 补充需求

以下条目来自需求评审，用于补全原始需求中未明确的约束。

### 2.1 验证与交付

- 需求进入工厂后，先由项目经理产出可检验的验收标准。
- 交付时必须附带验证证据：测试结果、QA 结论、验收标准逐条对照。无证据不视为交付。

### 2.2 角色间产物契约

- 角色之间通过产物协作，例如需求说明、架构设计、任务计划、代码变更、测试报告、QA 报告。
- 每种产物须定义结构、产出角色与消费角色。LangGraph 图状态以产物为单位组织，复盘打分以产物为依据。

### 2.3 人工关卡与异常处理

- 至少在需求确认、架构评审、最终交付三处设置人工关卡。
- 回退循环（例如测试失败退回程序员）须设重试上限，超限后升级给人处理。
- 任务中断后可从检查点续跑。

### 2.4 工作区隔离与权限

- 工厂自身代码与目标软件分离。每轮任务在独立的 git 工作树与分支上进行。
- 明确 Agent 的命令执行范围、是否允许推送远端，以及多角色并发写入时的冲突规避方式。

### 2.5 后端插件

- 插件接口声明各后端的能力（例如是否自带文件读写与命令执行工具），工厂在运行时校验角色所需能力是否满足。
- 每个角色可单独配置后端与模型；统一记录调用成本。

### 2.6 自我进化的约束

- 复盘由独立的评审角色执行，角色不给自身打分。
- 评分标准预先成文；打分须引用证据，例如返工次数、测试通过率、耗时、成本。
- Top3 改进点只形成改进提案，经人批准后才修改角色定义或流程，并留存版本记录。
- 维护固定的基准任务集；改进合入前后各运行一次，以数据确认改进有效。

### 2.7 角色边界

- 测试工程师：设计、编写、执行测试。
- QA：质量门禁。对照验收标准验收、审计流程合规，给出最终能否交付的结论。

### 2.8 可观测性

- 每轮任务记录输入、产物、对话记录、成本与复盘结果，作为复盘与进化的数据来源。

### 2.9 首个试点场景

- 先以小范围场景（单仓库、Python 小工具或小特性）跑通端到端流程，再扩展到 middleware 的 C/C++ 子仓。

### 2.10 与仓内现有资产的关系

- `agents/skills` 下已有代码开发、 JIRA操作、飞书协作等技能。工厂只按路径引用基础技能，不复制，也不反向依赖，也不引用任务编排等高级技能。
