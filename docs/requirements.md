# GeniStudio 需求

## 1. 原始需求

1. 这是一个自动化的 AI 软件工厂，接收人类输入的需求，产出经过验证的软件；
2. 包含不同角色的 Agent 定义，分为管理角色和执行角色。管理角色包括项目经理、架构师、QA、财务、代码评审、流程负责人和配置管理员，执行角色包括美工、UI、UX、程序员、测试工程师。执行角色和数量可根据需要扩展；
3. 每个角色有清晰的职责定义，有各自的原则和价值观，在工作流程和规则约束下工作；
4. 工作流程通过 LangGraph 编排；
5. 包括文档和代码等所有的输出产物都需要有模板或规范；
6. 承载软件工厂执行的 Agent 后端支持插件机制，默认使用 Cursor SDK，后续支持 OpenAI SDK 等其他 Agent SDK。
7. 调用Cursor SDK、OpenAI SDK或其它后端时，优先使用SDK默认模型或模型路由，能复用对应后端已有的MCP工具、规则、skill；
8. AI软件工厂适用的场景包括但不限于：通用软件开发（如Android/iOS App/Web/C++/python等）、特定领域软件开发(如依赖特定领域知识的GPU/NPU算子开发)
9. 本软件工厂和目标项目目录隔离，项目的顶层目录下自动创建.geni_studio目录存放项目级配置
10. 针对常用的软件开发场景，内置几套对应场景的配置，这些配置包括：工作流程、文档模板、输出的代码和文档的配置管理机制、可以调用的skill/MCP等工具；
11. 可扩展性需求：软件工厂的工作流程、文档模板、输出的代码和文档的配置管理机制、可以调用的skill/MCP等工具都可以按需配置和扩展；
12. 工厂支持自我进化：每一轮任务完成后，对模板、各个角色的输出以及流程自身进行复盘，以打分方式总结出 Top3 有价值的点和 Top3 需要改进的点。
13. 工厂自身的开发基于 Cursor IDE 进行，原始需求、项目计划等上下文信息在本目录自包含。
14. 人机交互需求：提供 CLI 和 Web 两套交互入口，提供：基础配置、项目级配置、运行状态观测、提示词输入、API key 配置、Curosr SDK等后端可选配置；
15. 工厂状态透明，web可以实时查看当前流程所在节点，飞书可以通过消息查询
16. 项目经理通过 Web 与飞书和人类沟通。不设项目经理 CLI 对话，命令行体验不适合澄清、批复和升级。
17. GeniStudio可用于对本项目自身进行递归开发和优化
18. 提供角色管理。可以在页面上增加、修改和删除角色。每个角色仍是一份 `roles/<标识>/role.md`，写明标题、类别、职责、原则与价值观、输入、输出和能力。人类关卡不是可管理的角色。已被任一流程引用的角色不能删除。

### 1.1 按既有条目归类的延续

以下条目来自 2026-11-08 的使用设想。它们不另起一套编号，归入上面最接近的原始需求。与已写条目不一致的地方，以本节为准，作为后续修订的依据。

延续需求 1：

- 人类专家把精力放在更有价值的事情上，例如找到真正有价值的需求、构建Agent工具、知识库、优化流程和模板等。
- 适用形态是：在明确的流程和模板支持下，让 Agent 长时间运行的生产力工具。不适合单次、小型任务。

延续需求 2：

- 增加合规管理角色，负责隐私、网络安全和知识产权合规。

延续需求 4 与需求 11：

- 使用顺序是三步。创建流程可选，不是每次都必须新建一份。创建项目必须选定所用流程；没有合适的流程时，先创建再选定。创建运行必须选定项目。
- 流程可以复制已有的一份，并裁掉多余节点。
- 流程编辑支持动态机制：节点可以动态并行、循环和按条件跳转。
- 子图可以保存，并在其他流程里复用。
- 并行包括两种：同一份方案由两路分别实现，用来对照；一个子系统拆成几个模块并行开发。
- 依赖关系如果成环，须规定最大循环次数。
- 任务异常后可以恢复并续跑。已有节点可以删除。

延续需求 8 与需求 10：

- 场景最终体现为流程。有了流程编辑器之后，不再单独保留场景设置，避免和流程编辑重复。
- 内置 NPU 算子开发流程，并保存为可复用的子图。
- 内置大语言模型整网适配或推理框架适配流程。整网或框架适配作为一项；拆出的算子开发调用算子开发子图并行进行，再做集成验证。

延续需求 6、需求 7 与需求 14：

- 每个项目可以为每个角色单独设置模型，按该项目的复杂度、重要性和成本来选，类似为人的项目选择不同成员。

延续需求 13：

- 用户说明补充总体架构，并写明上一节的适用形态。
- 项目目录补充安装说明。

## 2. 补充需求

以下条目来自需求评审，用于补全原始需求中未明确的约束。

### 2.1 验证与交付

- 需求进入工厂后，先由项目经理产出可检验的验收标准。
- 交付时必须附带验证证据：测试结果、QA 结论、验收标准逐条对照。无证据不视为交付。

### 2.2 角色间产物契约

- 角色之间通过产物协作，例如需求说明、架构设计、任务计划、代码变更、测试报告、QA 报告。
- 每种产物须定义结构、产出角色与消费角色。LangGraph 图状态以产物为单位组织，复盘打分以产物为依据。

### 2.3 人工关卡与异常处理

- 至少在需求确认、架构评审、最终交付三处设置人工关卡。
- 回退循环（例如测试失败退回程序员）须设重试上限，超限后升级给人处理。
- 任务中断后可从检查点续跑。

### 2.4 工作区隔离与权限

- 工厂自身代码与目标软件分离。每轮任务在独立的 git 工作树与分支上进行。
- 明确 Agent 的命令执行范围、是否允许推送远端，以及多角色并发写入时的冲突规避方式。

### 2.5 后端插件

- 插件接口声明各后端的能力（例如是否自带文件读写与命令执行工具），工厂在运行时校验角色所需能力是否满足。
- 每个角色可单独配置后端与模型；统一记录调用成本。

### 2.6 自我进化的约束

- 复盘由流程负责人与配置管理员执行：前者负责流程与角色，后者负责模板、规范与配置管理。二者不给自身产出打分：流程负责人不参与本轮任务执行；配置管理员承担本轮的配置管理工作，这部分由流程负责人评价。
- 评分标准预先成文；打分须引用证据，例如返工次数、测试通过率、耗时、成本。
- Top3 改进点只形成改进提案，经人批准后才修改角色定义或流程，并留存版本记录。
- 维护固定的基准任务集；改进合入前后各运行一次，以数据确认改进有效。

### 2.7 角色边界

- 测试工程师：设计、编写、执行测试。
- QA：质量门禁。对照验收标准验收、审计流程合规，给出最终能否交付的结论。

### 2.8 可观测性

- 每轮任务记录输入、产物、对话记录、成本与复盘结果，作为复盘与进化的数据来源。
- 一轮里每个角色的 Cursor 会话必须可观察。点开流程上的某一格，能按时间看到该角色在这一轮中的各次调用：发出的提示、助手回复、思考和工具调用。产物正文和成本行不够。

方案（尚未实现）：

- 会话按 `thread_id` 与角色分开。同一轮、同一角色继续用同一个 Agent；角色之间不共用。
- 调用时打开 SDK 的 `on_step`。步骤类型为助手消息、工具调用和思考。每步追加写入 `runs/<thread_id>/conversations/<角色>/<序号>.jsonl`。
- 同时记下该 Agent 的 `agent_id`、模型、这一次实际发出的提示和最终正文。`role.md` 只出现在该 Agent 的第一次提示里。
- 进程重启后，用保存的 `agent_id` 恢复只读查看；恢复失败时仍展示已落盘的 jsonl。
- Web 右侧在该节点产物之前增加「会话」一节，只读，不替代产物。节点仍在执行时，新的步骤随到随显示，不等该节点结束。现有状态帧要等节点结束才更新，所以会话增量要单独推送。

### 2.9 变更控制

- 已纳入基线的产物需要修改时，由发现问题的角色提出变更请求 `change_request`，写明修改对象、原因、受影响的验收标准或设计项。
- 影响验收标准或范围的变更，由项目经理评估并重新提交需求确认关卡；影响架构设计或任务计划的变更，由架构师评估并重新提交架构评审关卡。
- 变更获批后由原产出角色修改；配置管理员核对批准依据后登记到关卡与基线记录 `baseline_log`，缺少批准依据的修改不予登记。

### 2.10 项目经理与人类的即时通信（一期）

- 项目经理作为工厂对人类的 **统一沟通渠道**；除 Web 外，一期须支持 **飞书** 即时通信，用于：人工关卡等待时的通知与批复、需求澄清问答、财务预警与回退升级等经项目经理汇总后的 **人类决策**。
- **飞书**：应用机器人或单聊，支持消息推送、交互卡片（批准/驳回/跳转 Web）；入站消息与按钮回调须接入工厂 **同一套 HITL 接口**，与 Web 提交等价。
- **微信（含企业微信）**：**一期不做**。个人微信无稳定官方 Bot；在企业未统一使用企业微信或与飞书重复的前提下，企业微信回调一期 **不纳入** 范围；若后续有明确触达需求，单独 ADR 评审。
- **数据与审计**：IM 中的决策须写回图状态及 `baseline_log` / `requirement_spec` 等产物；`run_record` 记录通道类型、时间与摘要。IM 聊天记录仅作辅助证据，不替代结构化产物。
- **角色边界**：其他 Agent 角色 **不** 直接对人类开放飞书；多 Agent 之间 **不** 使用 IM 群聊协作（见 [ADR 0003](decisions/0003-pm-human-hitl-and-im-channels.md)）。
