# GeniStudio Web 与飞书的界面设计

- 日期：2026-11-06
- 性质：设计说明，不是已接受的技术决策，也不是实现
- 依据：[需求第 14、15、16 条](../requirements.md)；[竞品调研](../research/2026-11-06-agent-orchestration-web-ui.md)；[n8n 与 Dify 对照](../research/2026-11-06-n8n-dify.md)
- 视觉：页面使用 Web Awesome 免费核心（default 主题、default 色板、brand 蓝）。布局、当前节点和文案仍按本文。不使用 Pro 主题，不把页面改成营销页。

本文按产品操作界面来写。人来这里是为了启动一轮、看到走到哪、在关卡上做决定。界面应当消失在任务里。

## 1. 谁在用，要完成什么

主要使用者是工厂的人类决策者，通常是项目经理或需求提出者。两种情境：

- 坐在浏览器前，盯着一轮还在跑的任务，或刚被叫回来做关卡批复。
- 人在飞书里，只想知道「现在到哪了」，不想打开一整页日志。

成功的样子：不滚动长日志，就能指出当前节点、它前面完成了什么、这一步在等谁。飞书上的回答和 Web 上高亮的是同一个节点。

本工厂与开放式编码代理的差别：节点名单事先写在 LangGraph 里。进度是清单完成数，不是模型估计的剩余时间。

## 2. 选定方向

结构主张：页面上只放当前所处的那一个节点，不把整条流程铺开。摘要、产物和原始 JSON 挂在这一格上。节点清单仍在接口里，用来判断跳过和完成数，但不渲染成列表。

顺序：先看见当前节点，再决定要不要批复或打开产物。焦点就是这一格。

实现后果：轨道数据来自现有运行状态（阶段、下一节点、场景裁剪），不新造一套进度模型。地址栏继续用 `thread_id` 绑定这一轮。页面不提供在节点之间点选，因此不使用 `node` 参数。

## 3. 范围与边界

做：

- 人工处理页只显示当前流程节点，并让状态自行更新。
- 点节点后，右侧检视只显示这一节点的摘要和会话。
- 飞书识别状态问句，回复一张短卡片。
- 配置页保持现有结构：先选择，再单行，YAML 与 JSON 留在「原文」。写入凭证后做连通测试，页面不回显密钥。
- 运行中的一轮可以暂停。暂停留下现场，继续时从当前节点接着跑，不重做已完成的节点。

不做：

- 从旧检查点改状态再分叉。这和基线、变更控制冲突。
- 在网页里接管编辑器、终端或浏览器。
- 在运行页拖拽改流程。流程定义在「流程」页编排。角色的增加、修改和删除在「角色」页，不在运行页或流程页里做。
- 没有节点清单时编造完成百分比或剩余时间。
- 角色之间用即时通信互相聊天。对人类开口的仍只有项目经理。

## 4. 信息架构

六页，左栏一级菜单自上而下是项目、运行、流程、角色、配置、帮助。「角色」放在「流程」下面、「配置」上面。主题切换放在左栏底部，写要切换到的主题（「深色」或「浅色」）并配月亮或太阳图标；不再用浮在右下角的按钮，以免压住人工待办等右下角的表单。

| 页面 | 路径 | 人在这里做的事 |
|------|------|----------------|
| 项目 | `/project` | 新建一个项目，或打开已有项目并修改 |
| 运行 | `/?thread_id=<id>` | 启动一轮、看节点、批复关卡、读该节点的会话 |
| 流程 | `/workflow` | 新建或编辑一份流程，在泳道上编排活动和人类关卡 |
| 角色 | `/role` | 增加、修改或删除一个角色 |
| 配置 | `/config` | 填写与项目无关的 Agent、默认工作区、飞书和环境 |
| 帮助 | `/help#<topic>` | 阅读某一项配置或功能的说明，不能在这里修改 |
| 飞书卡片 | 无页面 | 读四行状态，或跳到上面的 Web 地址 |

`thread_id` 决定哪一轮。未启动时当前格是「启动」。主题存在服务端用户配置，多台机器共用，不进地址栏；浏览器只缓存一份供首屏使用（ADR 0026）。表单草稿、悬停和焦点也不进地址栏。

窄屏（约 900px 以下）：收起左栏。当前节点留在需求输入下方。检视改到它下面。批复表单仍留在主栏。

## 5. 节点轨道

页面按主路径列出本轮会执行的节点，使用中文短名。场景裁掉的节点，以及未打开的财务节点，不出现在轨道上。「启动」和「结束」不能被裁掉。内部机制节点 `pm_clarification_check`、`hitl_pause` 不单独出现；它们体现在当前格上。

计算时仍按下面的主路径理解位置。表里的顺序就是页面上的顺序。

| 顺序 | 节点标识 | 界面名称 |
|------|----------|----------|
| 1 | `run_start` | 启动 |
| 2 | `project_manager_draft` | 项目经理起草 |
| 3 | `tester_testability` | 可测性 |
| 4 | `gate_requirement_confirm` | 需求确认 |
| 5 | `config_manager_plan` | 配置计划 |
| 6 | `ux_designer` | 体验 |
| 7 | `ui_designer` | 界面 |
| 8 | `visual_designer` | 视觉 |
| 9 | `project_manager_scope` | 范围 |
| 10 | `architect` | 架构 |
| 11 | `gate_architecture_review` | 架构评审 |
| 12 | `developer` | 开发 |
| 13 | `change_control` | 变更 |
| 14 | `code_reviewer` | 评审 |
| 15 | `tester_execute` | 测试 |
| 16 | `qa` | 质量门禁 |
| 17 | `project_manager_delivery` | 交付汇总 |
| 18 | `gate_final_delivery` | 最终交付 |
| 19 | `config_manager_closeout` | 收口 |
| 20 | `process_owner_retro` | 复盘 |
| 21 | `run_end` | 结束 |

`run_start` 与 `run_end` 只出现在轨道上，不进入可执行图，也不能被场景裁掉。尚未启动时当前格是「启动」，状态为「初始」。本轮完成后当前格是「结束」，状态为「结束」；此前会执行的格子为「完成」。这两格的箭头不流动。

`escalate_dev_retry` 不插入主路径。开发回退超限时，当前格变为「等待人工」，待办类型写「升级」。

财务角色定义保留在 `roles/finance/role.md`。三个财务节点在 `workflow.features.finance` 打开时进入主路径和轨道，默认不打开，此时轨道上不显示。

每一格同时只有一种状态，用文字标签区分，不只靠颜色：

| 状态 | 标签 | 何时 |
|------|------|------|
| 尚未到达 | 未到 | 在当前节点之后，且本轮会执行 |
| 不启用 | 不显示 | 在本轮 `skip_nodes` 里，或财务开关关闭 |
| 已完成 | 完成 | 已经离开该节点，且不是当前 `next` |
| 进行中 | 进行中 | `next` 指向它，阶段不是等待人工，也不是已暂停 |
| 已暂停 | 已暂停 | 人按下「暂停」，执行停在当前格，现场仍在 |
| 等待人工 | 待批复 | 阶段为等待人工，且关卡或澄清落在这一格 |
| 初始 | 初始 | 尚未启动，当前格是「启动」 |
| 最终 | 结束 | 本轮已完成，当前格是「结束」 |

尚未启动时只列出本轮会执行的节点。「启动」为当前格，标签为「初始」，其余格子为「未到」，箭头停在「启动」上且不流动。已完成时，「结束」为当前格，标签为「结束」，此前会执行的格子为「完成」，箭头停在「结束」上且不流动。已暂停时箭头停在被暂停的那一格，连线不流动。

不在页面上显示「完成几 / 本轮几」。

回退（测试失败回到开发、变更退回需求确认或架构评审）时，当前格改成被退回的节点，箭头改指这一格。已经走过的格子保留在列表里。返回箭头的画法见 5.1。

### 5.1 泳道

宽屏（约 900px 及以上）把这条主路径排成泳道，并在中栏宽度内一次看全，不出现横向滚动。泳道按角色拆开。各泳道共用一条水平刻度表示执行顺序：越早的格子越靠左，越晚的越靠右。刻度按容器宽度排布。同一泳道里的格子互不重叠。某一角色本轮没有格子时，整条不出现。裁掉的节点继续不画。

| 泳道 | 格子 |
|------|------|
| 人类 | 启动、需求确认、架构评审、最终交付、结束 |
| 项目经理 | 项目经理起草、范围、交付汇总 |
| 配置管理员 | 配置计划、收口 |
| UX 设计师 | 体验 |
| UI 设计师 | 界面 |
| 美工 | 视觉 |
| 架构师 | 架构 |
| 程序员 | 开发、变更 |
| 代码评审 | 评审 |
| 测试工程师 | 可测性、测试 |
| QA | 质量门禁 |
| 流程负责人 | 复盘 |
| 财务 | 预算粗估、预算、成本快照 |

有人类格子时，人类泳道始终是第一行。子流程和并行若出现，排在人类下面，不能排到上面。其中三个关卡用黄底菱形岔路口标志表示需要人做选择，标志比普通节点图标大一半，活动名写在标志下方。关卡图标不代替中栏的批复表单。财务泳道仅在开关打开且本轮有财务格子时出现。相邻泳道用一深一浅两种背景区分，从第一行开始交替。

格子里写这一步的活动名。状态按本节用颜色区分，并在活动名前加一个文字符号，不只靠颜色：完成「✓」、进行中「●」（随运行闪烁）、等待人工或中断「!」、已暂停「‖」、已停止「■」、跳过「–」，未到达的格子不加；不把「完成」「进行中」等文字写进格子。泳道下方一行图例说明这些符号，以及「当前步骤」（实心强调色）与「右栏正在查看」（外框）的区别。已完成格子的文字与底色对比度不低于 4.5:1。泳道格子字号 12px，单行格子 13px。泳道名在每行左侧。除人类泳道固定写「人类」外，泳道名使用对应角色 `role.md` 的 `title`。

箭头只连接主路径上前后相邻的两格。连线从当前格的右侧引出，从下一格的左侧进入，拐弯用圆角。阶段为运行中时，只有指向当前格的那一段以虚线流动。发生回退、当前格落在已经走过的格子之前时，另画一条圆角返回箭头指向被退回的格子，流动的也改成这一段。等待人工、已暂停或已停止时，这段箭头停住并使用强调色。已结束时箭头停住，颜色与其他连线相同。

窄屏（约 900px 以下）不画泳道，退回单行：按主路径排成小按钮，一行放不下就换到下一行。点选、高亮和右栏检视与宽屏相同。宽屏时若中栏放不下主路径，即主路径上相邻两格无法左右分开并留出箭头，泳道整体加宽并在框内横向滚动，保留角色分道与回退箭头，不再退回单行；拖宽中栏或收窄右栏后恢复为不滚动。尚未选项目、没有可显示的流程时，标题下写「选择项目后，这里显示本轮要走的流程。」窄屏时检视与人工待办排在主栏下方，不压在左栏之下。

## 6. 人工处理页布局

保持现有三栏。

- 左栏：本轮标识，以及之后要补的 Run 列表。当前仍只有一轮时，列表里一项，空态写「尚未绑定」。
- 中栏：需求输入和人工待办保持现状。节点轨道放在待办上方，标题为「运行状态」，排法见 5.1。宽屏用泳道，窄屏退回单行。正在执行、等待人工、已暂停或已停止的当前格用强调色高亮，已完成的格子用灰色，尚未到达的格子用白色。指向当前格的连线用箭头标出；阶段为运行中时，这段连线以虚线流动，回退时这一段是返回箭头。点某一格，右侧改看这一步。人工待办容器与页面其他面板同一套底色和边框。「启动」只在尚未绑定或本轮已结束（已完成、已驳回、已停止）时可点。阶段为运行中或等待人工时，按钮变灰，文案改为「进行中」。同一行提供「暂停」和「停止」，直到本轮结束才收起；「停止」靠这一行右端放，与「启动」「暂停」拉开距离。「暂停」只在运行中可点。点「停止」先在按钮行下方展开确认：「停止会结束本轮，不能从当前节点接着跑。确认停止？」，按「确认停止」才发出请求，「取消」或 Esc 收起并把焦点还给「停止」。有人工待办时，泳道上方显示一条提示：「「节点名」等待你处理，表单在右侧「人工待办」。」与「去处理」按钮；按下后焦点落到待办表单的第一个选择控件，表单区短暂描边。人工待办表单的「提交并续跑」一行固定在待办区底部，内容较长时也不必滚动才能提交。右栏标题旁的阶段徽标写「本轮」加阶段（如「本轮等待人工」），表明它是整轮的阶段，不是所选步骤的状态。项目下方的提示写所选项目的流程（「流程：自我改进。」）；项目还没有流程时改用警示色写「这个项目还没有流程。」，并附「去项目页选择」链接直达该项目。项目类型已撤下（见 13.2），这里不再提示。停止会结束本轮，阶段变为已停止；正在执行的模型调用会被取消，若这次调用不能立刻返回，则在它结束后不再进入后续节点。暂停不结束本轮。
- 右栏：标题为当前节点的中文名。阅读方式见 6.2。不展示原始 JSON 状态。

关卡批复、澄清答复、升级选择仍用中栏已有表单。当前格不代替表单。

人工待办不铺陈产物正文。表单标题写决策点要人做什么（如「看结果：请批准，或不通过并前往「改代码」。」），标题已含节点名时不再另起一行重复。其下「待审阅」只列本次要看的产物：每项一行，写产物名、产出节点与字数；产物带结构化结论块时，另起一行标注「通过」或「未通过」、一句话结论与验收通过数。点产物名即选中产出它的节点，正文在右栏检视区按会话阅读。决策点审阅的产物按流程推导：内置关卡沿用固定清单；自定义决策点取上一个决策点之后各活动的输出；推导不出时才退回需求、代码变更、测试报告与交付报告。澄清与升级分别列出需求说明，以及代码变更、质量结论与成本。「关卡决定」中的不通过项写明去向：流程设了「不通过时前往」时写「不通过 — 退回「节点名」」，否则写「驳回 — 结束本轮」。正文仍由服务端读取，用于解析待办里的选择题与飞书卡片摘录。

点一个人曾经在上面做过决定的格子，右栏显示「决策记录」，每次一条，按先后排列。决策点的记录在决策点格子上；需求澄清与回退升级的记录在当时待办所在的格子上（澄清在提问的节点，升级在升级来源的节点），位于本步骤设置之下、会话之上。每条先写决定：决策点为「批准」「不通过 — 退回「节点名」」或「驳回 — 结束本轮」，澄清为「已答复」，升级为「继续重试」「暂停」或「终止本轮」；同行写类别（澄清、升级时）、第几次（多于一次时）、时间、渠道与批复人。其下是当时的待决内容、「当时的问题」（澄清时）、「当时待审阅」的产物清单与结构化结论（写法同人工待办，点产物名选中产出节点），最后是附言或答复原文。记录在提交时写入运行目录的 `decisions.jsonl`，从 Web、飞书与命令行提交都会记下。早于该文件的决策点批复只从基线记录补出决定、时间与附言，并注明「这次决定早于决策记录，只保留了决定、时间与意见。」带题组的澄清答复仍同时写回提问那次会话，题卡标出所选项。

等待人工超过时限（默认 24 小时，可用 `GENI_STUDIO_GATE_TIMEOUT_SECONDS` 覆盖）时，记一笔「超时未批复」。关卡仍停在原地，不自动批准或驳回。飞书卡片上的批复按钮不变。

状态更新：阶段为运行中或等待人工时，由服务端推送现有状态。已暂停时保留现场，不再推送；人按下继续并回到运行中之后，再恢复推送。阶段为已完成、已驳回或尚未启动时停止。请求未返回前不放转圈；轨道保持上一帧。读取失败时，需求输入下的错误行写「读不到这一轮的状态。检查服务是否还在，然后刷新。」轨道不清空。人离开页面即停止接收。页面上的阶段和错误文案不变。

动效：运行中的那一段箭头连线以虚线流动，周期约 1.1 秒。等待人工、已暂停、已停止或已结束时箭头停住。节点格子本身不播放位移动画。系统开启减少动态效果时，连线不流动。

### 6.1 暂停

暂停和停止是两件不同的事。停止结束本轮，阶段变为已停止，不能从原来的节点接着跑。暂停把这一轮留在原地：已完成的节点保持完成，当前格改为「已暂停」，阶段变为已暂停。现场、产物和 `thread_id` 都还在。

操作：

- 运行中：「暂停」与「停止」并列。暂停可点，停止仍可点。
- 已暂停：「暂停」换成「继续」。停止仍可点。「启动」保持不可用，避免另开一轮盖住现场。
- 等待人工：不提供暂停。这一轮已经停在关卡上，恢复方式仍是批复、澄清或升级选择。
- 已完成、已驳回、已停止、尚未启动：不提供暂停。

按下继续后，从被暂停的节点接着执行，不重做已经完成的格子。若暂停时模型调用还在进行，调用结束后不再进入下一节点，直到人按下继续。按下继续之后，从该节点重新进入执行。

文案：暂停成功后，待办上方写「本轮已暂停。已完成的节点不会重做。」继续之后这句消失，阶段回到运行中。暂停失败时写明原因，轨道保持暂停前的一帧。

飞书查询把阶段写为「已暂停」，当前行仍是这一格的中文名，待办写「无」。卡片不提供继续或停止。人要恢复，打开 Web。

### 6.2 右栏阅读

右栏顺序是：摘要（有待办摘要时出现）、会话（有记录或当前步执行中时出现）、活动节点的 Skill。右栏不再单独展示产物，产物正文即会话中的最终回复；无会话时不占位。节点格状态由标题旁阶段徽标表达，不在正文重复「状态」行。调用次数与开发重试计数不进右栏，成本账本原文不铺开。

会话除待批复的题卡外只读，最终回复按 Markdown 排版。判定类活动（评审、测试、QA）末尾的结论块（围栏语言 `verdict`）不显示 JSON 原文，改为结论卡片：先写「通过」或「未通过」与一句话结论，再按验收编号逐项标注通过、未通过或未验证；产物预览同样处理。结论块不是合法结论时按原文显示，便于看出格式错误。产物文件里的结论块原样保留，供判定、验收覆盖与复盘读取。会话与活动节点的 Skill 两节不设「会话」「Skill」小标题，内容本身已足以辨识。同一节点的每一次调用（「第 N 次」）可折叠，默认只展开最近一次；人展开或收起的状态在状态刷新与新步骤到达时保持。助手回复按段落。工具调用每次一行，只写动作与对象（如「读取 docs/a.md」「执行 pytest -q」「搜索 关键词 · 目录」），失败时标注「失败」，不展示参数与返回内容；相邻的调用收成一组，已结束的一次超过三条时收起为「工具调用 N 次」。思考只显示文字，相邻的合并，默认收起并标注用时。运行中新步骤追加在这一节，不等节点结束：只重绘会话这一节，不重建右栏的模型设置与 Skill；内容未变时不重绘。重绘前停在底部的，重绘后仍贴着底部显示最新输出；已向上翻看的保持阅读位置，滚动条不随新步骤跳动。折叠块的展开或收起在点击时即记下，不等浏览器随后派发的切换事件，以免推送重绘恰好落在两者之间时丢失。会话内可单独滚动的块（提示原文、代码与工具输出、表格）按节点记下横向与纵向滚动位置，状态刷新或新步骤到达而重绘后恢复，不回到最左或最上。Codex 后端只把完成的条目与出错写入会话记录，逐字增量与用量刷新不落盘，会话推送的体积随步骤数而非字数增长。

子代理单独成块，不收进工具调用组：首行为「子代理 + 任务描述 + 状态」，状态为运行中、完成、失败或已转入后台；次行写子代理类型、模型、工具调用次数与用时；子代理的回复或错误收在「结果」「错误」折叠块中，不展示其内部步骤。子代理开始时即出现「运行中」，完成后原位换成结果。后台命令在命令行尾标注：这一轮带标识的进程中仍有对应命令时标「后台 · 运行中」（悬停显示 pid）；命令写法为后台（`nohup`、`setsid`、结尾 `&`）但进程已不在时标「后台 · 已结束」。这一轮仍有进程运行时，会话顶部列出「本轮仍在运行的进程 N 个」，每行为命令、pid 与已运行时长，并说明本轮完成、驳回或停止时一并结束（见 ADR 0021）。

回复中供人点选的 A/B/C 选项（形如「A（推荐）：…」，允许加粗与列表符）画成题卡，放在这一次回复之后，参照 Cursor 会话中的提问卡：题干取选项前紧邻的一句问话，每个选项一行并带勾选框，推荐项标注「推荐」；题干与选项行不再在回复正文中重复。等待人工批复且题组与人工待办中的选项一致时，题卡可直接点选，并与人工待办中的同组选项双向同步；选中即在附言中写入一行「选择 X：…」，改选时原位替换，随批复一并提交。人从 Web、飞书或命令行任一渠道提交后，答复写回提出这些题的那一次会话：题卡转为只读并标出所选项，其下显示「人工答复 · 批准」等决定与附言原文。同一次会话只记录第一次答复。人工待办中的选择题不再需要「填入附言」这一步，点选即写入附言；多题时用「上一题」「下一题」切换。

## 7. 配置页

项目、运行、流程、配置和帮助共用同一套三栏。项目放最上面，二级菜单是「新建」「打开」和「从目录打开」。运行原名人工处理，二级菜单是「新建 Run」与 Run 列表（含阶段筛选）；泳道与人工待办在中栏与右栏同屏展示，不再单独设「运行状态」「待办」导航。泳道标题仍叫「运行状态」，以免与一级菜单「流程」重名。流程页的二级菜单是「新建」「编辑」和「导入」，编排方式见第 8 节。配置只保留与具体项目无关的共性项，按 Agent、工作区、飞书分成二级菜单。环境是只读清单，放在配置页右栏，不进左栏。字段种类不改。帮助放在配置下面，说明见第 8.1 节。

### 7.0 项目的新建与打开

「新建」和「打开」是同一份项目字段的两个入口。项目类型、通知不再各占一个二级菜单，改为主栏里的分组。右栏仍查看项目类型原文和合并结果，不进左栏。

下面的分组是当前页面。§1.1 要改掉其中的场景设置，并要求项目必须选定流程，改法见第 13 节。

主栏分组，自上而下：

1. 标识。新建时不手填，按标题自动生成。打开后只读，不能改已有项目的标识。
2. 说明。标题、说明、远程仓库、工作区。
3. 项目类型。项目类型、设计轨、节点裁剪。
4. 通知。飞书通知群、飞书通知人。
5. 其它。流程、开发重试上限。流程是下拉列表，选项为已保存的流程，可以不指定。

新建：

- 地址是 `/project#new`。
- 字段从空白开始，可以直接填写。只写标题，不写项目标识。标题必填。
- 标识在按下「创建」时生成一次。名称本身已符合标识规则时原样保留，例如 `Demo_001`。其余英文名称整理成小写并用 `-` 连接。名称含中文时，先译成英文，再整理成标识，例如「预览流程」得到 `preview-workflow`。已有同名标识时，后面加 `-2`、`-3`。翻译失败时改用 `project-1` 这类序号，不因此取消创建。
- 创建后标识只读。以后修改标题，标识不变。
- 主按钮是「创建」。创建成功后进入打开，地址改为 `/project?project=<id>#open`，按钮下写「已创建项目 <id>。」
- 创建失败留在新建，按钮下写明原因。

打开：

- 地址是 `/project?project=<id>#open`。没有 `project` 时停在选择，不自动打开某一个。
- 先选择项目。未选时，其余字段不可编辑，选择框下写「先选择要打开的项目。」
- 还没有任何项目时，写「还没有项目。」旁边是「新建」，进入新建档。
- 主按钮是「打开」。按下后才载入该项目的字段，地址改为 `/project?project=<id>#open`。
- 项目已经打开后，「保存」是次要按钮。
- 换项目或离开这一档时，若字段已改且未保存，先问「放弃未保存的修改？」确认后才切换。取消则留在当前项目。

从目录打开：

- 地址是 `/project#from-directory`。
- 只填一个目录，必须是服务进程能读取的绝对路径。编辑框可以手填，右侧是打开文件夹按钮。选定目录后直接打开，不再另放「打开」。手填的路径按回车打开。目录列表里，鼠标所在的一行用底色和边框标出当前焦点。
- 打开已有项目时，若项目还没有远程仓库地址，且该仓库能解析出符合规则的远端地址，则写入项目。新建时同样写入。优先用 origin，没有 origin 时用第一个远端。
- 这个目录已经是某个项目的工作区：进入打开，并选中那个项目。多于一个项目指向同一目录时，先列出这些项目，人选定后再进入打开。
- 目录是 git 仓库，且还没有项目指向它：只补项目类型。项目标识按目录名自动生成，规则与新建项目相同；中文目录名会译成英文。项目类型必填。按钮是「创建并打开」。成功后进入打开，工作区就是这个目录。标题用目录名。
- 目录不存在、不是目录、不是 git 仓库，或是工厂仓库本身：留在这一档，按钮下写明原因，不创建项目。

进入「项目」时：地址带 `project` 就打开该项目；地址是 `#new` 就进入新建；地址是 `#from-directory` 就从目录打开；三者都没有时，已有项目则进入打开的选择态，没有项目则进入新建。这三档只放在左栏。「从目录打开」使用打开的文件夹图标。窄屏时左栏收成图标，这三档仍从左栏进入。

运行页仍只选择已有项目来启动，不在运行页新建项目。

运行页先选择项目，再填写交付目标。项目同一行有「Run 命名」，默认为项目标识加连字符和递增序号（如 `_example-1`），启动前可以改。本轮按所选项目的流程执行，页面不提供项目类型选择；老项目文件里遗留的 `scenario_key` 仍由后端兼容读取，但不再在页面上展示或提示（见 13.2）。

启动前的改动自动保存为草稿（ADR 0026）：选了项目且填过内容后，交付目标、Run 名称、附件、节点 Skill 与角色模型、推理强度、上下文、Fast 停笔约 1 秒即存到服务端，成功后写「已自动保存，尚未启动。」；切换 Run、新建、复制或关闭页面前先存一次。组合不受支持等设置问题未解决时不自动保存，问题照常写在设置区下方。「保存 Run 配置」（次要按钮，紧挨「启动」右侧）立即保存一次，不启动、不调用模型，成功后写「已保存 <Run 名称>，尚未启动。」Run 列表中该项状态为「已保存」，可打开继续修改、复制或删除；启动后该份配置转为正式 Run，原记录删除。Run 启动后不再显示此按钮，因为状态由服务端自动保存。这里只保存本轮，不改 `.env` 或项目配置。

- 项目、项目类型、设计轨、节点裁剪、流程、后端、飞书后端用选择。流程列出已保存的流程，可以不指定。
- 标题、说明、远程仓库、重试上限、工作区、通知群、通知人、模型、默认工作区、Web 地址、API Key 用单行。远程仓库填 git 远端地址，可空，放在说明之下、工作区之上。项目工作区是待开发项目的 git 目录；留空时用运行配置里的默认工作区，默认工作区也留空时用 `workspaces/项目名`。
- `scenario.yaml` 和合并 JSON 只在「原文」里。
- 未选项目时，项目字段不可编辑。空态文案维持「先选择项目，或新建一个。」

### 7.1 凭证的连通测试

Agent 的 API Key，以及飞书后端选「应用凭据」时要写入的凭据，属于工厂级凭证。它们只出现在「配置」里，不进项目配置，也不出现在运行页。页面不回显已保存的密钥；环境列表只显示是否已配置。

按下「写入 .env」后，先保存，再对本次生效的凭证做一次连通测试。测试用当前选中的后端和模型。模型留空则按该后端的默认模型或自动路由测试。人这次没有改密钥时，用已经保存的值测试，输入框仍保持空白。密钥留空且从未配置时，不发起测试，环境列表保持「未配置」。

结果写在「写入 .env」下方，不弹新页：

- 已连通：写「已连通。」环境列表里对应项改为已配置。
- 连不上：写「连不上。」下一句说明原因和下一步，例如密钥无效、地址不可达或飞书应用凭据不匹配。已写入的值不自动删掉，避免一次探测失败把原配置清掉。
- 测试尚未返回：按钮保持忙碌，不重复提交。轨道和项目表单不受这次测试影响。

飞书后端选 lark-cli 时，不把应用密钥当必测项。连通测试改为确认本机 lark-cli 是否可用，结果仍写在同一处。默认工作区只检查路径是否可写，不把它当成凭证。

## 8. 飞书状态卡片

问句（整句去空白后）命中下列之一才算查询，不触发批准或驳回：`状态`、`到哪了`、`到哪`、`进度`、`status`。

回复一张卡片，四行，顺序固定：

1. 阶段：未启动 / 运行中 / 已暂停 / 中断 / 等待人工 / 已完成 / 已驳回 / 已停止。
2. 当前：轨道上的中文名。没有运行时写「还没有进行中的轮次」。
3. 待办：无关卡时写「无」。有关卡时写待办类型和关卡中文名，例如「待批复 · 需求确认」。
4. 打开：Web 链接，带 `thread_id`。没有运行时省略此行。

卡片不附模型原文、不附完整成本账本。人要看产物，用链接回到 Web。

同一会话里若有多轮，卡片回答最近一轮仍在进行、已暂停、中断或等待人工的；都已结束则回答最近一轮，并在阶段行写明已完成或已驳回。不在卡片里做选择器。已暂停或中断的卡片不提供继续或停止。待办卡片里若有多道选择题组，列出各题选项；单题仍用点选按钮，多题引导至 Web 逐题点选或在附言中写明各题选择。

## 8. 流程编排

流程页用来编写一份以后可以反复运行的流程。它和运行页上的泳道用同一套画法，但运行页只读，流程页可改。复制、子图、并行和循环次数还没有控件，见第 13 节。

左栏「流程」放在「运行」下面、「配置」上面。二级菜单是「新建」「编辑」和「导入」。主栏顶部不再重复这三档。窄屏收起左栏后，仍从左栏图标进入。

一份流程是活动、人类关卡、启动和结束的排列。活动按执行顺序从左到右。角色分成泳道。有人类格子时，人类泳道始终是第一行，子流程和并行排在它下面。启动和结束放在人类泳道，是普通胶囊，不能删除，也不能跳过。人类关卡用岔路口图标，名称写在图标下面，并且只能留在人类泳道。活动名称写在节点里面。定义本身没有「完成」或「进行中」，那些状态只出现在运行页。

连线从节点右侧流出，从下一节点左侧流入，折角用圆角。回退从较晚的节点右侧绕回较早节点的左侧，不从上面或下面接入。同一泳道里的节点不重叠。没有活动的角色不占一条泳道。

角色名单来自 `roles/`。泳道和角色选择显示 `role.md` 的 `title`，与运行页泳道相同。换泳道只是把已有活动交给另一个已有角色，不能在这里新增角色，也不能改角色文件里的原则和默认产物。这个活动自己的输入、输出和模板写在节点上。节点裁剪仍留在项目或项目类型里，不写进流程定义。本页不能启动一轮。运行页以后再选择要用哪一份流程，这次不改运行页的启动表单。

地址：

- 新建是 `/workflow#new`。
- 编辑是 `/workflow?workflow=<id>#edit`。没有 `workflow` 时停在选择，不自动载入某一个。`#open` 与 `#edit` 相同。
- 进入「流程」时：地址带 `workflow` 就载入该流程；地址是 `#new` 就进入新建；都没有时，已有流程则进入编辑的选择态，没有流程则进入新建。

标识与项目使用同一套生成规则。打开后标识只读。

新建：

- 只写标题和说明，不写流程标识。标题必填。说明可空。
- 「创建」紧挨在标题和说明下面。写好这两项就可以创建，不必先编排节点。
- 标识在按下「创建」时按标题生成一次。中文标题译成英文后再整理。重名时加 `-2`、`-3`。翻译失败时用 `workflow-1` 这类序号，不因此取消创建。创建后修改标题，标识不变。
- 创建成功后进入编辑，地址改为 `/workflow?workflow=<id>#edit`，按钮下写「已创建流程 <id>。」这时才展开下面的编辑区。编辑区里先只有「启动」和「结束」，中间一条连线。
- 创建失败留在新建，写明原因。

编辑：

- 先选择流程。未选时画布不可编辑，选择框下写「先选择要编辑的流程。」
- 选中一份后立刻载入并画出泳道，不再另放「打开」。
- 选择框在载入后仍然可用，不灰掉。再选另一份就换过去。
- 还没有任何流程时，写「还没有流程。」旁边是「新建」。
- 流程已经载入后，编辑区最下面是「保存」。原文默认收起，只在载入后可以覆盖。
- 换流程或离开这一档时，若已改且未保存，先问「放弃未保存的修改？」确认后才切换。取消则留在当前流程，选择框回到刚才那一份。

中栏标题是「编排」，样式与运行页的「运行状态」相同。标题和说明放在编排区最上面，选中节点时仍然留在那里。

宽屏使用泳道。节点要保持能点中的宽度。节点多到一行放不下时，中栏可以横向滚动。运行页仍必须一眼看全、不横向滚动；编排页留出可点的目标，所以允许滚动。窄屏改为按执行顺序排列的单列，仍可选中、改顺序和删除，不把泳道挤成一团。

添加和修改：

- 「添加活动」先选择角色，再写活动名。角色列表第一项是「人类」。选人类时，这个节点成为人工关卡，名称写在岔路口图标下，并落在人类泳道。选其他角色时，新活动出现在「结束」之前，并落在该角色的泳道最右侧。新活动先带上该角色 `role.md` 里的输入和输出名字，模板留空，等选中后再补。
- 「添加关卡」同样进入人类泳道，位置在「结束」之前。决策点要选择决定类型，目前为「批准或驳回」。未选择决定类型的决策点不能启动。
- 点一个节点，右栏改看这一节点。点空白处，右栏回到流程说明。
- 活动和关卡都可以改名称和所属角色。所属角色一变，节点就换到对应泳道。改成人类时，节点成为人工关卡；改成其他角色时，关卡成为该角色的活动。启动和结束不能改名，也不能删除。
- 删除写在右栏，要再确认一次。删掉之后，前后节点按原来的先后重新连上。
- 沿水平方向拖动节点，松手后按从左到右重排。拖动不改变角色；换角色用右栏的选择。

右栏在没有选中节点时，只说明标识如何生成。选中活动时，自上而下是活动名、角色、输入、输出、前面和后面的节点。选中关卡时是决策点和前后节点。选中启动或结束时，只说明这两格不能删除、不能跳过。启动、结束和决策点没有输入、输出和模板。

宽屏时，右栏左缘有一条竖向分隔，可访问名称是「拖动调整检视栏宽度」。指针放上去变成左右调整。按住向左拖，右栏变宽、中栏变窄；向右拖则相反。宽度有下限，保证名称和模板地址还能读。上限是当前视口的整个宽度，可以一直拖到铺满。左栏右缘的分隔同样可以拖到整个视口宽度。松开后记住这次宽度。运行页和配置页的右栏使用同一宽度。焦点在分隔上时，左右方向键每次移动一小段。窄屏不显示这条分隔，右栏改到中栏下面。

活动的输入和输出：

- 输入、输出都在右栏显式列出，不把角色文件里的名单藏起来当作已经填好。角色文件只在新建活动时给一份初始名字。
- 每一项输入是一个产物名。可以手写，也可以从更早活动的输出里选。另外始终可以选「人类需求」，它不是某个活动的输出。同一活动里名字不能重复。列表从上到下，就是运行时交给这个角色的顺序。一项都没有时，写「这个活动不读取已有产物。」
- 每一项输出是一个产物名，并且必须带一份模板。同一活动里输出名字也不能重复，也不能和本活动的输入重名。一项都没有时，写「这个活动还没有输出。」
- 换角色时，若输入和输出仍是上一个角色带进来的初始名字、而且模板都还空着，就换成新角色的名字，模板继续空着。人已经改过名单或模板时，保持不动。
- 保存可以留下模板还没写完的草稿。启动一轮时，活动没有输出，或某项输出没有模板，就拒绝启动，并写明是哪一个活动、哪一项输出。

输出的模板：

- 模板正文不在这里编辑。每一项输出的地址栏上方标出「模板」，再二选一：本地文件，或一个链接。
- 本地文件是服务进程能读取的文件绝对路径。编辑框可以手填，右侧是选择文件。选定后把路径写入该项。路径不存在、不是文件，或进程读不到时，写在该项下面。
- 链接是 `http` 或 `https` 地址。写成别的形式时，写在该项下面。
- 同一项输出只保留当前选中的那一种。从「本地文件」改成「链接」，或反过来，清掉原来的地址。
- 模板用来约束这项输出的结构。运行时把模板交给该活动的角色，模型按模板写这项输出。

## 8.1 帮助

中栏标题就是二级菜单的名字。正文按条目排列，每条仍是完整句子。不放操作按钮，也不复述字段的占位符。各篇条目如下。

概览：

- GeniStudio 接收人的交付目标，按项目绑定的流程让各角色写出文档和代码，并在决策点停下来等人批复。
- 工厂自身和待开发项目分开。
- 左栏自上而下是项目、运行、流程、角色、配置和帮助。
- 项目决定这一轮用哪份流程、哪一种项目类型。运行看这一轮走到哪。流程编排活动和决策点。角色页增加、修改和删除角色。配置填写与具体项目无关的后端、工作区、飞书和环境。
- 它适合已经有明确流程和模板、需要 Agent 长时间运行的工作。不适合单次、小型任务。

架构：

- GeniStudio 把人的交付目标交给项目所绑定的流程。
- 流程由活动和决策点组成。活动按角色写出文档或代码，决策点停下来等人批复。
- 工厂仓库和待开发项目分开。项目只选定流程、模型和通知，不在页面上另设一套场景。
- 它适合已经有明确流程和模板、需要 Agent 长时间运行的工作。不适合单次、小型任务。

条目下面放架构图。蓝框是 GeniTech，灰框是第三方。层次和框内名称与所定稿的架构图一致。

入门指南：

- 安装步骤写在仓库的 README，完整说明在 docs/install.md。装好后打开这个 Web 页面。
- 在「配置」的 Agent 中选择后端。想先熟悉界面，选 stub，它不调用 Cursor。
- 要让角色真正工作时，选 cursor 或 codex。API Key 只有一个输入框，文字随后端变化。密钥只保存，页面不回显。默认模型是每一轮里角色没有另选模型时使用的模型，留空则用该后端自己的默认模型。写完后按「写入 .env」。
- 工作区可以先空着。项目里填写的工作区优先于默认工作区。飞书可以以后再配。
- 先准备流程，再新建项目并选定该流程，然后到运行里选定项目并启动。决策点在待办里批准或驳回。

项目：

- 可以新建、打开，或从本机的 git 目录创建。
- 新建只写标题。标识按标题生成，中文标题会译成英文。打开之后标识只读。
- 从目录打开时，标识按目录名生成，工作区就是这个目录。
- 项目里可以选择项目类型、设计轨、节点裁剪、通知对象、远程仓库、工作区和流程。流程可以不指定。

运行：

- 先选择项目，再填写交付目标并启动。名称默认是项目标识加递增序号，启动前可以改。
- 未启动的 Run 改动后自动保存为草稿；「保存 Run 配置」立即保存一次。保存内容为交付目标、附件、各节点的 Skill、各角色的模型、推理强度、上下文与 Fast，暂不启动。之后可从 Run 列表打开，修改后再启动。
- 中栏是这一轮的泳道，只列出当轮会走到的节点。可以进行中暂停、继续或停止。
- 决策点、需求澄清和回退升级停在待办里，批复后继续。
- 点一个格子，右栏查看这一步的会话。活动节点在右栏顶部先显示本步骤设置，会话接在其下；未启动、运行中与已结束的 Run 布局相同。设置区分两组，各带一个外框：「角色属性」放模型摘要，点开在菜单里调整模型、推理强度、上下文与 Fast（见 §13.7），绑定角色，同一角色在泳道中的所有节点共用；「步骤属性」放 Skill，只属于这一步，占满组宽。MCP 是全局配置，不在这里选择，只读列在配置页的 Agent 下（见 §8.1「Agent」）。两组始终并排，平分横向空间，拖动右栏宽度时同比伸缩；变窄时模型摘要先截去推理强度等标记，再截断模型名。模型菜单与摘要左对齐，宽度不小于摘要，不超出设置区。说明统一写在两组下方，只写有信息量的内容：读取失败、组合不受支持、运行中修改从下一次调用起生效。不写「已跑过、不能再改」「这一轮已经结束、不能再改」一类可由禁用状态看出的提示。只读状态下没有选择的 Skill 栏写「未添加。」名单由当前后端查出。Skill 栏标题与「模型」的标签同字号同间距；每个已选项一行，依次是名称框、删除按钮（与左栏 Run 列表相同的垃圾桶图标，悬停变为危险色），最后一行在删除按钮之后接「增加」，没有已选项时只有「增加」。名称框与下拉框同高、单行显示，过长以省略号截断，悬停显示全名和描述。点「增加」弹出列表（背景与 hover 与 `wa-select` 列表一致），左栏的列表左对齐、右栏的列表右对齐，不超出右栏；鼠标移到某项时在项下方浮出描述；指针移出列表区域或点页面其它位置时列表自动收起。同一流程节点在不同 Run 里可以各选各的。还没跑到的节点可以改；已经跑过的只显示。添加的 Skill 只提示这一步优先使用；不添加时由 Agent 按需选用后端已加载的 Skill。

流程：

- 可以新建、编辑或导入一份流程。新建只写标题，标识按标题生成。编辑时选中一份就载入，选择框保持可用。
- 宽屏用泳道排列活动和决策点。右栏左缘可以拖动。
- 活动要写出输入和输出。每项输出要有模板，模板是本地文件或 http、https 链接。
- 决策点目前的决定类型是批准或驳回。选进项目后，下一轮按这些节点执行。
- 活动没有输出，或某项输出没有模板时，不能启动。

角色：

- 左栏「角色」放在「流程」下面、「配置」上面。可以新建、打开、修改和删除。
- 新建只写标题。标识按标题生成，中文标题会译成英文。打开之后标识只读。
- 打开后可以改标题、类别、职责、原则与价值观、输入、输出和能力。
- 输入和输出从工厂已有的产物名里选择。人类关卡不在这个列表里。
- 已被流程使用的角色不能删除。先从那些流程里去掉，再删角色。
- 新建活动时，用该角色文件中的输入和输出名字作为初值。模板仍要在流程页补上。
- 合规管理负责隐私、网络安全和知识产权，不代替 QA 的交付结论。

Agent：

- 在「配置」的 Agent 中选择后端。stub 不调用外部模型。
- cursor 使用 Cursor SDK，并复用该工作区里已有的工具、规则和 Skill。codex 使用 Codex SDK。
- 默认模型是每一轮里角色没有另选模型时使用的模型。留空则用该后端自己的默认模型。API Key 只有一个输入框，文字随后端变化，只写入本机配置，页面不回显。
- MCP 是全局配置，对所有角色可见，不按角色或节点选择。默认模型（Codex 时为推理强度）下方只读列出所选后端会加载的 MCP 服务器，宽度与上方控件一致，每行左侧是名称，右侧标注来源「项目」或「用户」：cursor 读取当前打开项目的工作区与用户目录的 `.cursor/mcp.json`，codex 读取 `~/.codex/config.toml` 的 `mcp_servers`；切换后端或项目后刷新。没有配置时写「没有配置 MCP 服务器」，stub 时不列出。增删在对应后端的配置里进行，页面不提供编辑。

工作区：

- 默认工作区在项目没有填写工作区时使用。
- 一轮任务在待开发项目自己的目录里进行，不改工厂仓库里的源码。
- 项目里填写的工作区优先于这里的默认值。

飞书：

- 飞书用来通知和批复，和网页上的待办是同一套决定。
- 可以填写飞书后端、卡片里的 Web 地址、默认通知群和默认通知人。
- 项目里另外填写的通知群或通知人优先于这些默认值。

环境：

- 配置页右栏按 Agent、工作区、飞书分成三组。每一项左侧是名称，右侧是是否已配置。有具体取值时写在名称下面。
- 密钥只显示已配置，不写出原文。
- 飞书命令行单独成组，安装、配置和发消息各占一行。说明按条目列在这组下面。

## 9. 状态与文案

| 情境 | 轨道 | 主栏或状态条 |
|------|------|----------------|
| 尚未启动 | 不画格 | 「还没有运行记录。填写交付目标并启动后，阶段和会话会显示在这里。」（右栏单行显示，不换行） |
| 读取中，已有上一帧 | 保持当前这一格 | 「正在读取状态」 |
| 读取失败 | 保持当前这一格 | 「读不到这一轮的状态。检查服务是否还在，然后刷新。」 |
| 未知的 `thread_id` | 不画格 | 「没有这一轮。核对地址栏中的 thread_id。」 |
| 刚启动，首个节点尚未排出 | 不标当前格，各格待执行 | 与「运行中」相同。启动或续跑任务仍在执行时，服务端不把这一帧报为「已完成」或「已驳回」，推送与页面都不会提前停止 |
| 运行中 | 一格「进行中」 | 「启动」变灰，文案为「进行中」；旁边是「暂停」和「停止」 |
| 已暂停 | 停在被暂停的格，标签「已暂停」 | 「本轮已暂停。已完成的节点不会重做。」「继续」可点，「停止」可点 |
| 等待人工 | 一格「待批复」 | 中栏展开现有批复表单；「启动」仍为灰色的「进行中」，「停止」可点；不提供暂停 |
| 已完成 | 本轮会走的格均为「完成」 | 「这一轮已结束。右侧是最后一步的产物。」右栏默认检视最后一个执行过的节点，而不是「结束」。「停止」收起 |
| 已驳回 | 停在被驳回的关卡，该格标「待批复」且表单不再提交 | 「这一轮已驳回。」 |
| 已停止 | 停在被停止的节点，该格标「已停止」 | 「这一轮已停止。」「启动」恢复可点 |
| 场景跳过 | 当前节点不会是被跳过的格 | 无额外句子 |

按钮和错误沿用现有说法：保存、创建、取消、提交并续跑、暂停、继续、停止。凭证测试的结果用「已连通」或「连不上」。错误写明原因和下一步，不用感叹句。计数用阿拉伯数字。

## 10. 无障碍与实现约束

- 轨道是一行可横向滚动的小按钮。当前格用 `aria-current` 和按钮名称里的状态文字暴露给读屏，不单靠颜色。
- 点某一格，右侧检视改看这一步；再点当前正在执行的格，检视回到这一步。
- 阶段胶囊使用礼貌的实时区域，阶段变化时读出新标签，不打断输入。
- 对比度沿用现有浅色与深色令牌。深色背景保持现在的近黑，正文不用纯白。
- 不新增图标库。主栏阶段仍用文字标签。左栏运行列表的阶段和删除用图标，名称和阶段写在可访问名称里。每项次行写最近更新时间（当天写时分，其余写月日与时分），悬停提示含名称、阶段与更新时间。「复制」与删除只在鼠标悬停或键盘焦点落在该项时显示，当前打开的一项与触屏设备上常显。运行中是转圈并旋转，已停止是方块，等待人工是三角感叹号。系统开启减少动态效果时转圈停住。确认删除仍用文字。
- 悬停只改变背景，且仅在有鼠标的设备上。触控点击区域不小于 44px。
- 不使用会带动布局的动画。减少动效时去掉透明度过渡。

## 11. 尚未决定

- Run 列表来自检查点。左栏标题为「Run列表」，可按阶段筛选，其中「全部」列出已有轮次。点进一轮仍用现有轨道和 `thread_id`。每一行的阶段和删除是图标，悬停可读出阶段和名称；确认删除仍要再点一次文字按钮。后返回的旧筛选结果不能盖住当前选择。
- 轮询 2 秒是否在长任务上过于频繁。若服务端推送更容易接在现有运行服务上，实现时可以替换，界面文案不变。
- 飞书上「最近一轮」以本聊天绑定为准，还是以项目配置里的通知对象为准。实现前需要定一条，避免同一群里答错轮次。

## 13. §1.1 的界面

第 7 节和第 8 节描述已经做出来的页面。本节描述 §1.1 要改成的样子。没写到的控件保持原样。帮助正文仍按条目写完整句子。

### 13.1 使用顺序

三步的顺序固定，页面上的空态按这个顺序指路。

1. 流程可以不新建。已经有可选用的流程时，直接去建项目。
2. 项目必须选定一份流程。没有合适的，按钮写「去创建流程」，进入 `/workflow#new`。项目页的流程选择去掉「不指定」。还没有任何流程时，不能创建项目，选择框下写「还没有流程。先创建一份。」
3. 运行必须先选定项目。未选时「启动」不可用，选择框下写「先选择项目。」项目还没有流程时，不启动，写「这个项目还没有流程。」

从目录创建项目时，补的是流程，不再补项目类型。未选流程时，按钮不可用。

内置可直接选用的流程包括通用软件开发和自我改进，名称写在选择框里，不把「不指定」当成默认图的入口。通用软件开发仍走工厂默认图。自我改进按听清改动、确认、改代码、自行核对、看结果、写交付说明、确认入库、提交入库执行，并且直接改目标仓库当前检出的分支。

### 13.2 撤下场景设置

项目主栏去掉「项目类型」「设计轨」和「节点裁剪」。节点要不要留下，在流程里删除，不在项目里打勾。

项目右栏不再展示项目类型原文和合并结果。改成「所选流程」：流程标题、标识，以及活动与决策点的数量。还没选时写「还没有选定流程。」

配置页不放这些字段。帮助里「项目」一节改成：项目选定流程、通知、远程仓库和工作区。不再写项目类型、设计轨和节点裁剪。

### 13.3 复制流程

流程的「编辑」一档，选定一份之后有「复制」。复制生成新的一份，标题是「副本 · 原标题」，标识按标题重新生成，节点和模板地址一并带上。成功后进入这份新流程的编辑区，人再删掉不要的节点。不另做批量裁剪表。

内置流程可以复制，不能直接改原件。载入内置流程时，编辑控件不可用，只留「复制」。右栏写「这是内置流程。要改，先复制一份。」

### 13.4 循环次数

节点右栏已有「回退到」。选了回退目标之后，在它下面增加「最大循环次数」，必填，整数，至少为 1。没选回退目标时不显示这一项。

提示写「到达这个次数后，停下来等人处理。」保存时若回退已选而次数为空，写「先写最大循环次数。」运行到达次数后，待办类型仍是升级，不自动再跑。

### 13.5 子图

编辑区增加「存为子图」和「插入子图」。

「存为子图」把当前流程另存成一份可复用的子图，要写子图标题。成功后写「已存为子图 <标识>。」原流程仍留在编辑区。

「插入子图」是一个选择。选定后，在「结束」之前插入一格，格子里写子图标题。点这一格，右栏只读列出它内部的活动和决策点，并有「打开子图」。打开后去编那一份子图，不在当前流程里改它的内部。

内置两份，出现在「插入子图」的列表里，标记「内置」：

- NPU 算子开发。先写算子合同，再确认做 CCA、AOM 或两者。两条通路是可复用子图。两者都做时先 CCA 后 AOM，然后共同评审。
- 大语言模型整网适配或推理框架适配。这一份的说明写在右栏：整网或框架适配是一项；拆出的算子开发会插入 NPU 算子开发子图，并行完成后再做集成验证。第一版不在页面上再拆一层自由嵌套。

### 13.6 并行和条件

并行是编辑区里的一种节点，名称由人写。它的右栏列出支路，至少两条。每条支路有名称，以及这一条上的活动顺序。「添加支路」增加一条。删到只剩一条时，写「并行至少要有两条支路。」

两路对照用同一个控件：两条支路，支路名由人写，例如「实现甲」「实现乙」。子系统拆模块也用它，支路名就是模块名。画布上，这一格比普通活动宽，里面并排写出支路名。运行时，支路同时进行；都结束后才进入下一格。

条件跳转第一版不写表达式。决策点增加「不通过时前往」。通过仍进入下一格；驳回不再直接结束本轮，而前往所选的已有节点。未选时，驳回仍结束本轮，和现在一样。

### 13.7 运行里的角色模型

角色模型、推理强度、上下文与 Fast 属于角色配置，放在运行页右栏顶部的本步骤设置区，与该节点的 Skill 并排；中栏和项目页不再列出角色清单。点一个活动节点，右栏「角色属性」组内显示一枚模型摘要，依次写模型、推理强度、上下文与 Fast（仅在开启时写出），沿用默认的项以浅色显示，悬停显示各项全称。点摘要弹出菜单，交互参照 Cursor IDE 的模型菜单：首页依次是 Fast 开关、上下文、推理强度、分隔线、模型，每行右侧写当前值，沿用默认时注明「默认」；鼠标移到上下文、推理强度或模型一行，或键盘焦点落到这一行时，该项的取值列表作为子菜单在首页旁边弹出，不遮挡首页：优先放在右侧，右侧放不下（右栏紧贴窗口右缘时即如此）改放左侧，并在窗口内上下收拢；移到 Fast 行或另一行时随之切换或收起。子菜单不设「沿用默认」一项，Fast 行也不写「沿用默认」：没有本轮选择时，实际生效的值（项目配置或模型默认）直接打勾，选回这个值即清除本轮选择、恢复沿用；只有默认值不在列表中时才另列一项（如后端目录没有标出默认模型时的「后端默认」）。Codex 未配置模型时，以目录中 `is_default` 标出的模型作为生效模型，按它给出推理强度与 Fast，选它即沿用后端默认。当前值打勾，模型默认值与项目配置的推理强度另行标注；模型列表带搜索框，每个模型后附其默认推理强度。焦点停在一级行上时只弹出子菜单，焦点不移动；点击该行或按右方向键才进入子菜单，模型页的焦点落在搜索框；在子菜单中按左方向键或 Esc 收起子菜单并回到对应一级行。选定后子菜单收起，菜单保持打开；点页面其它位置或在一级菜单中按 Esc 收起整个菜单。状态刷新重绘右栏时，菜单保持打开，原先弹出的子菜单与搜索词保留，焦点原在搜索框的仍回到搜索框；换到其它角色的节点或切换 Run 时收起。模型目录未声明的项不出现在首页；Auto 模型时推理强度一行禁用并写「由 Auto 决定」。推理强度、Fast 与上下文随模型保存，与 Cursor IDE 相同：改动其中一项时记下当前模型的取值，换模型时换上新模型上次的取值，没记过的回到默认；记忆按角色与模型存在服务端用户配置中，多台机器打开同一服务共用（ADR 0025）。后端按角色取值（`model_for_role`、`effort_for_role`），流程节点不单独指定模型；同一角色在一个 Run 中共用一个会话（ADR 0020），模型与推理强度相同。人类与决策点不显示这些设置。读取角色设置失败时，不停留在「正在读取」，而写明失败原因，并提示刷新或重启服务。

「模型」列出当前后端模型目录，「沿用默认」表示沿用配置里的默认模型。「推理强度」只列出所选模型支持的级别，并标注模型默认值：Cursor 后端读取 `Cursor.models.list` 中该模型的推理参数（`effort`、`reasoning_effort` 或 `reasoning`）；Codex 后端读取 `supported_reasoning_efforts`。模型为 Auto 或目录未声明推理参数时，推理强度不可选。换模型后原级别不受支持时，保留原值并提示重新选择，启动与保存均拒绝该组合。

「上下文」只对 Cursor 后端、且模型目录声明了参数 `context` 的模型出现（如 Claude Opus 5.5 的 300K 与 1M、GPT-5.5 的 272K 与 1M），取值与显示名取自目录，默认值取自默认变体；「沿用默认」不传参数。按角色保存在 `role_model_params`，这是推理强度与 Fast 之外、由目录声明的模型参数的通用映射（ADR 0025）。Codex 后端没有可选的上下文档位，不显示这一项。`thinking` 等其它目录参数不开放，始终沿用模型默认。

「Fast」是开关：显示当前生效的开或关，沿用默认时左侧注明；拨到与模型默认相同的值即回到沿用默认。只有模型目录声明了 Fast 的模型才显示：Cursor 后端读取模型参数 `fast`（取值 `true`/`false`，默认值取自默认变体）；Codex 后端读取 `service_tiers` 中的 Fast 档（旧目录为 `additional_speed_tiers`），调用时以 `service_tier` 传给本轮调用，「关」传 `default`。Auto 模型或所选模型没有 Fast 时，不能指定开或关，启动与保存均拒绝该组合。Fast 模式按更高费率计费。

部分 Cursor 模型并非所有组合都可用，例如 GPT-5.5 与 GPT-5.4 的 1M 上下文不能开 Fast。模型目录以变体列出允许的组合，页面与后端都按它校验：与当前显式选择冲突的取值禁用，悬停说明「与当前其它设置不能同时使用」；显式选择本身允许、但与沿用默认的项拼起来不在目录里时，把需要变动的默认项改为离默认最近的允许取值并写成本轮选择，在设置区下方说明改了什么（如「已同时把上下文设为 272K」）。后端调用前再按目录校验一次，组合不在目录里时报错，未选的项按默认补齐会越界时显式传入补齐后的取值。

每一轮 Run 各自保存。同一角色在不同轮次里可以选不同模型、推理强度、上下文与 Fast。换项目后按新流程重列角色。这一轮已经结束时，摘要禁用、不能展开，只以禁用状态表示，不另写说明。这里不选后端，后端仍在配置页。

### 13.8 合规角色

不新开页面。`roles/` 里增加合规管理之后，流程的角色选择和泳道会显示它的标题，规则与其他角色相同。帮助「角色」补一条：合规管理负责隐私、网络安全和知识产权，不代替 QA 的交付结论。

### 13.9 中断后续跑

暂停后的「继续」不变。

一轮因为服务中断或节点失败而停住、人并没有按「停止」时，运行页在「启动」旁边显示「续跑」。旁边写「这一轮在中途中断。已完成的节点不会重做。」「续跑」从中断的节点接着做。「启动」仍会新开一轮，避免和续跑混在同一个按钮里。

### 13.10 帮助和安装说明

帮助在「概览」和「入门指南」之间增加「架构」，地址 `/help#architecture`。条目：

- GeniStudio 把人的交付目标交给项目所绑定的流程。
- 流程由活动和决策点组成。活动按角色写出文档或代码，决策点停下来等人批复。
- 工厂仓库和待开发项目分开。项目只选定流程、模型和通知，不在页面上另设一套场景。
- 它适合已经有明确流程和模板、需要 Agent 长时间运行的工作。不适合单次、小型任务。

概览补上最后一条的适用形态。「入门指南」的项目步骤改为：先准备流程，再新建项目并选定该流程，然后到运行里选定项目并启动。

安装步骤不放进网页表单。README 保留最短四步，完整说明和给 Agent 的执行契约写在 `docs/install.md`。帮助「入门指南」第一条改为：安装步骤写在仓库的 README，完整说明在 docs/install.md。装好后打开这个 Web 页面。

## 14. 角色管理

依据需求第 18 条。本节页面已经实现。左栏一级菜单「角色」放在「流程」下面、「配置」上面，图标风格与其他一级菜单相同。进入这一页时，左栏展开二级菜单「新建」和「打开」。人类关卡不出现在名单里，也不能在这里新建。

角色仍写入 `roles/<标识>/role.md`。标识在创建时按标题生成一次，规则与项目、流程相同。创建后标识只读，再改标题也不改标识。

新建：

- 地址是 `/role#new`。
- 中栏先只放标题。「创建」放在标题下面。标题必填。未写标题时写「先写标题。」
- 创建成功后进入打开，地址改为 `/role?role=<id>#open`，按钮下写「已创建角色 <id>。」这时才展开编辑区。
- 新建后的类别默认是执行角色。

打开：

- 地址是 `/role?role=<id>#open`。没有 `role` 时停在选择，不自动打开某一个。
- 先选择角色。未选时，其余字段不可编辑，选择框下写「从列表中选择角色即可编辑。」
- 还没有任何角色时，写「还没有角色。先新建一个。」旁边是「新建」。
- 选中一份后立刻载入字段，不再另放「打开」。载入后「选择角色」仍留在编辑区最上方，便于切换到下一个角色；其下才是「标题」与其余字段。
- 换角色或离开这一页时，若字段已改且未保存，先问「放弃未保存的修改？」

编辑区自上而下：

1. 标题。
2. 类别。选择「管理角色」或「执行角色」。
3. 职责。可增删的条目，至少一条。空着保存时写「先写一条职责。」
4. 输入。从工厂已有产物名里选择，可以一项都没有。不提供手写，避免写出图状态里没有的名字。
5. 输出。同样从已有产物名里选择，至少一项。空着保存时写「先选择一项输出。」
6. 能力。三项可勾选：读取文件、写入文件、运行命令。都不勾选时可以保存。提示写「不勾选时，这个角色只写文字，不读写文件，也不运行命令。」
7. 原则与价值观。一段正文，写入 `role.md` 正面的原则、价值观、工作方式和禁止事项。空着保存时写「先写原则与价值观。」

「保存」放在编辑区最下面。保存成功写「已保存 <id>。」修改写入角色文件。已经在跑的轮次仍用启动时读到的定义，下一轮才用改后的内容。

删除只在打开后出现，放在「保存」旁边。先问「删除「<标题>」？」已被任一已保存流程引用时不删除，写「这个角色还在流程里：<流程标题>。先从这些流程里去掉。」引用包括活动、并行支路里的活动，以及这些流程所插入的子图。删除成功后回到选择态，写「已删除角色。」

右栏标题是「角色说明」。未选中时写「标识按标题自动生成。中文标题会译成英文。创建后不再改变。」打开后另写标识，以及「出现在这些流程里」或「还没有流程用到它。」右栏不放表单。

流程页的角色选择和运行泳道继续使用这里保存的标题。输入和输出的初值仍取自该角色文件。模板仍在流程页填写。
