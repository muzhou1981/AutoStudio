# auto_studio Web 与飞书的界面设计

- 日期：2026-11-06
- 性质：设计说明，不是已接受的技术决策，也不是实现
- 依据：[需求第 14、15、16 条](../requirements.md)；[竞品调研](../research/2026-11-06-agent-orchestration-web-ui.md)；[n8n 与 Dify 对照](../research/2026-11-06-n8n-dify.md)
- 视觉：页面使用 Web Awesome 免费核心（default 主题、default 色板、brand 蓝）。布局、当前节点和文案仍按本文。不使用 Pro 主题，不把页面改成营销页。

本文按产品操作界面来写。人来这里是为了启动一轮、看到走到哪、在关卡上做决定。界面应当消失在任务里。

## 1. 谁在用，要完成什么

主要使用者是工厂的人类决策者，通常是项目经理或需求提出者。两种情境：

- 坐在浏览器前，盯着一轮还在跑的任务，或刚被叫回来做关卡批复。
- 人在飞书里，只想知道「现在到哪了」，不想打开一整页日志。

成功的样子：不滚动长日志，就能指出当前节点、它前面完成了什么、这一步在等谁。飞书上的回答和 Web 上高亮的是同一个节点。

本工厂与开放式编码代理的差别：节点名单事先写在 LangGraph 里。进度是清单完成数，不是模型估计的剩余时间。

## 2. 选定方向

结构主张：页面上只放当前所处的那一个节点，不把整条流程铺开。摘要、产物和原始 JSON 挂在这一格上。节点清单仍在接口里，用来判断跳过和完成数，但不渲染成列表。

顺序：先看见当前节点，再决定要不要批复或打开产物。焦点就是这一格。

实现后果：轨道数据来自现有运行状态（阶段、下一节点、场景裁剪），不新造一套进度模型。地址栏继续用 `thread_id` 绑定这一轮。页面不提供在节点之间点选，因此不使用 `node` 参数。

## 3. 范围与边界

做：

- 人工处理页只显示当前流程节点，并让状态自行更新。
- 点节点后，右侧检视只显示这一节点的摘要、产物和成本。
- 飞书识别状态问句，回复一张短卡片。
- 配置页保持现有结构：先选择，再单行，YAML 与 JSON 留在「原文」。写入凭证后做连通测试，页面不回显密钥。
- 运行中的一轮可以暂停。暂停留下现场，继续时从当前节点接着跑，不重做已完成的节点。

不做：

- 从旧检查点改状态再分叉。这和基线、变更控制冲突。
- 在网页里接管编辑器、终端或浏览器。
- 拖拽重组角色。角色仍由 `roles/<name>/role.md` 定义。
- 没有节点清单时编造完成百分比或剩余时间。
- 角色之间用即时通信互相聊天。对人类开口的仍只有项目经理。

## 4. 信息架构

三页，左栏一级菜单自上而下是项目配置、运行、配置。主题切换仍是右下角按钮。

| 页面 | 路径 | 人在这里做的事 |
|------|------|----------------|
| 项目配置 | `/project` | 选择项目，填写场景绑定、设计轨、节点裁剪、工作区和通知 |
| 运行 | `/?thread_id=<id>` | 启动一轮、看节点、批复关卡、读该节点的产物 |
| 配置 | `/config` | 填写与项目无关的 Agent、默认工作区、飞书和环境 |
| 飞书卡片 | 无页面 | 读四行状态，或跳到上面的 Web 地址 |

`thread_id` 决定哪一轮。未启动时当前格是「启动」。主题仍只存在本地，不进地址栏。表单草稿、悬停和焦点也不进地址栏。

窄屏（约 900px 以下）：收起左栏。当前节点留在需求输入下方。检视改到它下面。批复表单仍留在主栏。

## 5. 节点轨道

页面按主路径列出全部节点，使用中文短名。跳过的节点仍留在列表里，标签为「跳过」。内部机制节点 `pm_clarification_check`、`hitl_pause` 不单独出现；它们体现在当前格上。

计算时仍按下面的主路径理解位置。表里的顺序就是页面上的顺序。

| 顺序 | 节点标识 | 界面名称 |
|------|----------|----------|
| 1 | `run_start` | 启动 |
| 2 | `project_manager_draft` | 项目经理起草 |
| 3 | `tester_testability` | 可测性 |
| 4 | `gate_requirement_confirm` | 需求确认 |
| 5 | `config_manager_plan` | 配置计划 |
| 6 | `ux_designer` | 体验 |
| 7 | `ui_designer` | 界面 |
| 8 | `visual_designer` | 视觉 |
| 9 | `project_manager_scope` | 范围 |
| 10 | `architect` | 架构 |
| 11 | `gate_architecture_review` | 架构评审 |
| 12 | `developer` | 开发 |
| 13 | `change_control` | 变更 |
| 14 | `code_reviewer` | 评审 |
| 15 | `tester_execute` | 测试 |
| 16 | `qa` | 质量门禁 |
| 17 | `project_manager_delivery` | 交付汇总 |
| 18 | `gate_final_delivery` | 最终交付 |
| 19 | `config_manager_closeout` | 收口 |
| 20 | `process_owner_retro` | 复盘 |
| 21 | `run_end` | 结束 |

`run_start` 与 `run_end` 只出现在轨道上，不进入可执行图，也不能被场景裁掉。尚未启动时当前格是「启动」，状态为「初始」。本轮完成后当前格是「结束」，状态为「结束」；此前会执行的格子为「完成」。这两格的箭头不流动。

`escalate_dev_retry` 不插入主路径。开发回退超限时，当前格变为「等待人工」，待办类型写「升级」。

财务角色定义保留在 `roles/finance/role.md`。概算、预算、成本三个节点的函数还在 `workflows/default.py`，当前图不注册、不连边。需要时再接回流程。

每一格同时只有一种状态，用文字标签区分，不只靠颜色：

| 状态 | 标签 | 何时 |
|------|------|------|
| 尚未到达 | 未到 | 在当前节点之后，且本轮会执行 |
| 被场景跳过 | 跳过 | 在本轮 `skip_nodes` 里 |
| 已完成 | 完成 | 已经离开该节点，且不是当前 `next` |
| 进行中 | 进行中 | `next` 指向它，阶段不是等待人工，也不是已暂停 |
| 已暂停 | 已暂停 | 人按下「暂停」，执行停在当前格，现场仍在 |
| 等待人工 | 待批复 | 阶段为等待人工，且关卡或澄清落在这一格 |
| 初始 | 初始 | 尚未启动，当前格是「启动」 |
| 最终 | 结束 | 本轮已完成，当前格是「结束」 |

尚未启动时列出全部节点。「启动」为当前格，标签为「初始」，其余未跳过的格子为「未到」，箭头停在「启动」上且不流动。已完成时，「结束」为当前格，标签为「结束」，此前会执行的格子为「完成」，箭头停在「结束」上且不流动。已暂停时箭头停在被暂停的那一格，连线不流动。

不在页面上显示「完成几 / 本轮几」。

回退（测试失败回到开发、变更退回需求确认或架构评审）时，当前格改成被退回的节点，箭头改指这一格。已经走过的格子保留在列表里。

## 6. 人工处理页布局

保持现有三栏。

- 左栏：本轮标识，以及之后要补的 Run 列表。当前仍只有一轮时，列表里一项，空态写「尚未绑定」。
- 中栏：需求输入和人工待办保持现状。节点轨道放在待办上方，按主路径把全部节点排成小按钮，一行放不下就换到下一行。正在执行、等待人工、已暂停或已停止的当前格用强调色高亮，已完成和跳过的格子用灰色，尚未到达的格子用白色。指向当前格的连线用箭头标出；阶段为运行中时，这段连线以虚线流动。点某一格，右侧改看这一步。人工待办容器与页面其他面板同一套底色和边框。「启动」只在尚未绑定或本轮已结束（已完成、已驳回、已停止）时可点。阶段为运行中或等待人工时，按钮变灰，文案改为「进行中」。同一行提供「暂停」和「停止」，直到本轮结束才收起。「暂停」只在运行中可点。停止会结束本轮，阶段变为已停止；正在执行的模型调用会被取消，若这次调用不能立刻返回，则在它结束后不再进入后续节点。暂停不结束本轮。
- 右栏：标题为当前节点的中文名。内容顺序为：这一格的状态标签、摘要、该节点产物的节选、成本账本里属于这一节点的行、测试或 QA 证据（若有）。原始 JSON 仍折叠，标题用「原始状态」。

关卡批复、澄清答复、升级选择仍用中栏已有表单。当前格不代替表单。

状态更新：阶段为运行中或等待人工时，每 2 秒读一次现有状态接口。已暂停时保留现场，不再按 2 秒轮询；人按下继续并回到运行中之后，再恢复轮询。阶段为已完成、已驳回或尚未启动时停止。请求未返回前不放转圈；轨道保持上一帧。读取失败时，需求输入下的错误行写「读不到这一轮的状态。检查服务是否还在，然后刷新。」轨道不清空。人离开页面即停止轮询。

动效：运行中的那一段箭头连线以虚线流动，周期约 1.1 秒。等待人工、已暂停、已停止或已结束时箭头停住。节点格子本身不播放位移动画。系统开启减少动态效果时，连线不流动。

### 6.1 暂停

暂停和停止是两件不同的事。停止结束本轮，阶段变为已停止，不能从原来的节点接着跑。暂停把这一轮留在原地：已完成的节点保持完成，当前格改为「已暂停」，阶段变为已暂停。现场、产物和 `thread_id` 都还在。

操作：

- 运行中：「暂停」与「停止」并列。暂停可点，停止仍可点。
- 已暂停：「暂停」换成「继续」。停止仍可点。「启动」保持不可用，避免另开一轮盖住现场。
- 等待人工：不提供暂停。这一轮已经停在关卡上，恢复方式仍是批复、澄清或升级选择。
- 已完成、已驳回、已停止、尚未启动：不提供暂停。

按下继续后，从被暂停的节点接着执行，不重做已经完成的格子。若暂停时模型调用还在进行，调用结束后不再进入下一节点，直到人按下继续。按下继续之后，从该节点重新进入执行。

文案：暂停成功后，待办上方写「本轮已暂停。已完成的节点不会重做。」继续之后这句消失，阶段回到运行中。暂停失败时写明原因，轨道保持暂停前的一帧。

飞书查询把阶段写为「已暂停」，当前行仍是这一格的中文名，待办写「无」。卡片不提供继续或停止。人要恢复，打开 Web。

## 7. 配置页

项目配置、运行和配置共用同一套三栏。项目配置放最上面，二级菜单是项目、场景和通知。运行原名人工处理，二级菜单是新建 Run、流程、待办和当前轮次。配置只保留与具体项目无关的共性项，按 Agent、工作区、飞书、环境分成二级菜单。字段种类不改。

运行页先选择项目，再填写交付目标。项目同一行有「Run 命名」，默认为项目标识加连字符和递增序号（如 `_example-1`），启动前可以改。场景只在项目配置里绑定一次，启动时沿用所选项目的 `scenario_key`，页面不再提供场景选择。

- 项目、场景、设计轨、节点裁剪、后端、飞书后端用选择。
- 标题、说明、重试上限、流程配置名、工作区、通知群、通知人、模型、默认工作区、Web 地址、API Key 用单行。项目工作区是待开发项目的 git 目录；留空时用运行配置里的默认工作区，默认工作区也留空时用 `workspaces/项目名`。
- `project.yaml`、`scenario.yaml` 和合并 JSON 只在「原文」里。
- 未选项目时，项目字段不可编辑。空态文案维持「先选择项目，或新建一个。」

### 7.1 凭证的连通测试

Agent 的 API Key，以及飞书后端选「应用凭据」时要写入的凭据，属于工厂级凭证。它们只出现在「配置」里，不进项目配置，也不出现在运行页。页面不回显已保存的密钥；环境列表只显示是否已配置。

按下「写入 .env」后，先保存，再对本次生效的凭证做一次连通测试。测试用当前选中的后端和模型。模型留空则按该后端的默认模型或自动路由测试。人这次没有改密钥时，用已经保存的值测试，输入框仍保持空白。密钥留空且从未配置时，不发起测试，环境列表保持「未配置」。

结果写在「写入 .env」下方，不弹新页：

- 已连通：写「已连通。」环境列表里对应项改为已配置。
- 连不上：写「连不上。」下一句说明原因和下一步，例如密钥无效、地址不可达或飞书应用凭据不匹配。已写入的值不自动删掉，避免一次探测失败把原配置清掉。
- 测试尚未返回：按钮保持忙碌，不重复提交。轨道和项目表单不受这次测试影响。

飞书后端选 lark-cli 时，不把应用密钥当必测项。连通测试改为确认本机 lark-cli 是否可用，结果仍写在同一处。默认工作区只检查路径是否可写，不把它当成凭证。

## 8. 飞书状态卡片

问句（整句去空白后）命中下列之一才算查询，不触发批准或驳回：`状态`、`到哪了`、`到哪`、`进度`、`status`。

回复一张卡片，四行，顺序固定：

1. 阶段：未启动 / 运行中 / 已暂停 / 等待人工 / 已完成 / 已驳回 / 已停止。
2. 当前：轨道上的中文名。没有运行时写「还没有进行中的轮次」。
3. 待办：无关卡时写「无」。有关卡时写待办类型和关卡中文名，例如「待批复 · 需求确认」。
4. 打开：Web 链接，带 `thread_id`。没有运行时省略此行。

卡片不附模型原文、不附完整成本账本。人要看产物，用链接回到 Web。

同一会话里若有多轮，卡片回答最近一轮仍在进行、已暂停或等待人工的；都已结束则回答最近一轮，并在阶段行写明已完成或已驳回。不在卡片里做选择器。已暂停的卡片不提供继续或停止。

## 9. 状态与文案

| 情境 | 轨道 | 主栏或状态条 |
|------|------|----------------|
| 尚未启动 | 不画格 | 「还没有运行记录。填写交付目标并启动。」 |
| 读取中，已有上一帧 | 保持当前这一格 | 「正在读取状态」 |
| 读取失败 | 保持当前这一格 | 「读不到这一轮的状态。检查服务是否还在，然后刷新。」 |
| 未知的 `thread_id` | 不画格 | 「没有这一轮。核对地址栏中的 thread_id。」 |
| 运行中 | 一格「进行中」 | 「启动」变灰，文案为「进行中」；旁边是「暂停」和「停止」 |
| 已暂停 | 停在被暂停的格，标签「已暂停」 | 「本轮已暂停。已完成的节点不会重做。」「继续」可点，「停止」可点 |
| 等待人工 | 一格「待批复」 | 中栏展开现有批复表单；「启动」仍为灰色的「进行中」，「停止」可点；不提供暂停 |
| 已完成 | 本轮会走的格均为「完成」 | 「这一轮已结束。右侧是最后一步的产物。」「停止」收起 |
| 已驳回 | 停在被驳回的关卡，该格标「待批复」且表单不再提交 | 「这一轮已驳回。」 |
| 已停止 | 停在被停止的节点，该格标「已停止」 | 「这一轮已停止。」「启动」恢复可点 |
| 场景跳过 | 当前节点不会是被跳过的格 | 无额外句子 |

按钮和错误沿用现有说法：保存、创建、取消、提交并续跑、暂停、继续、停止。凭证测试的结果用「已连通」或「连不上」。错误写明原因和下一步，不用感叹句。计数用阿拉伯数字。

## 10. 无障碍与实现约束

- 轨道是一行可横向滚动的小按钮。当前格用 `aria-current` 和按钮名称里的状态文字暴露给读屏，不单靠颜色。
- 点某一格，右侧检视改看这一步；再点当前正在执行的格，检视回到这一步。
- 阶段胶囊使用礼貌的实时区域，阶段变化时读出新标签，不打断输入。
- 对比度沿用现有浅色与深色令牌。深色背景保持现在的近黑，正文不用纯白。
- 不新增图标库。状态用文字标签。
- 悬停只改变背景，且仅在有鼠标的设备上。触控点击区域不小于 44px。
- 不使用会带动布局的动画。减少动效时去掉透明度过渡。

## 11. 尚未决定

- Run 列表的数据从哪来。现在接口按 `thread_id` 读取一轮，没有「最近若干轮」的列表。左栏列表可以后做，轨道不依赖它。
- 轮询 2 秒是否在长任务上过于频繁。若服务端推送更容易接在现有运行服务上，实现时可以替换，界面文案不变。
- 飞书上「最近一轮」以本聊天绑定为准，还是以项目配置里的通知对象为准。实现前需要定一条，避免同一群里答错轮次。
