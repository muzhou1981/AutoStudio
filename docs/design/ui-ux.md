# AutoStudio Web 与飞书的界面设计

- 日期：2026-11-06
- 性质：设计说明，不是已接受的技术决策，也不是实现
- 依据：[需求第 14、15、16 条](../requirements.md)；[竞品调研](../research/2026-11-06-agent-orchestration-web-ui.md)；[n8n 与 Dify 对照](../research/2026-11-06-n8n-dify.md)
- 视觉：页面使用 Web Awesome 免费核心（default 主题、default 色板、brand 蓝）。布局、当前节点和文案仍按本文。不使用 Pro 主题，不把页面改成营销页。

本文按产品操作界面来写。人来这里是为了启动一轮、看到走到哪、在关卡上做决定。界面应当消失在任务里。

## 1. 谁在用，要完成什么

主要使用者是工厂的人类决策者，通常是项目经理或需求提出者。两种情境：

- 坐在浏览器前，盯着一轮还在跑的任务，或刚被叫回来做关卡批复。
- 人在飞书里，只想知道「现在到哪了」，不想打开一整页日志。

成功的样子：不滚动长日志，就能指出当前节点、它前面完成了什么、这一步在等谁。飞书上的回答和 Web 上高亮的是同一个节点。

本工厂与开放式编码代理的差别：节点名单事先写在 LangGraph 里。进度是清单完成数，不是模型估计的剩余时间。

## 2. 选定方向

结构主张：页面上只放当前所处的那一个节点，不把整条流程铺开。摘要、产物和原始 JSON 挂在这一格上。节点清单仍在接口里，用来判断跳过和完成数，但不渲染成列表。

顺序：先看见当前节点，再决定要不要批复或打开产物。焦点就是这一格。

实现后果：轨道数据来自现有运行状态（阶段、下一节点、场景裁剪），不新造一套进度模型。地址栏继续用 `thread_id` 绑定这一轮。页面不提供在节点之间点选，因此不使用 `node` 参数。

## 3. 范围与边界

做：

- 人工处理页只显示当前流程节点，并让状态自行更新。
- 点节点后，右侧检视只显示这一节点的摘要、产物和成本。
- 飞书识别状态问句，回复一张短卡片。
- 配置页保持现有结构：先选择，再单行，YAML 与 JSON 留在「原文」。写入凭证后做连通测试，页面不回显密钥。
- 运行中的一轮可以暂停。暂停留下现场，继续时从当前节点接着跑，不重做已完成的节点。

不做：

- 从旧检查点改状态再分叉。这和基线、变更控制冲突。
- 在网页里接管编辑器、终端或浏览器。
- 在运行页拖拽改流程。流程定义在「流程」页编排。角色仍由 `roles/<name>/role.md` 定义，页面上不能新建角色。
- 没有节点清单时编造完成百分比或剩余时间。
- 角色之间用即时通信互相聊天。对人类开口的仍只有项目经理。

## 4. 信息架构

五页，左栏一级菜单自上而下是项目、运行、流程、配置、帮助。主题切换仍是右下角按钮。

| 页面 | 路径 | 人在这里做的事 |
|------|------|----------------|
| 项目 | `/project` | 新建一个项目，或打开已有项目并修改 |
| 运行 | `/?thread_id=<id>` | 启动一轮、看节点、批复关卡、读该节点的产物 |
| 流程 | `/workflow` | 新建或打开一份流程，在泳道上编排活动和人类关卡 |
| 配置 | `/config` | 填写与项目无关的 Agent、默认工作区、飞书和环境 |
| 帮助 | `/help#<topic>` | 阅读某一项配置或功能的说明，不能在这里修改 |
| 飞书卡片 | 无页面 | 读四行状态，或跳到上面的 Web 地址 |

`thread_id` 决定哪一轮。未启动时当前格是「启动」。主题仍只存在本地，不进地址栏。表单草稿、悬停和焦点也不进地址栏。

窄屏（约 900px 以下）：收起左栏。当前节点留在需求输入下方。检视改到它下面。批复表单仍留在主栏。

## 5. 节点轨道

页面按主路径列出本轮会执行的节点，使用中文短名。场景裁掉的节点，以及未打开的财务节点，不出现在轨道上。「启动」和「结束」不能被裁掉。内部机制节点 `pm_clarification_check`、`hitl_pause` 不单独出现；它们体现在当前格上。

计算时仍按下面的主路径理解位置。表里的顺序就是页面上的顺序。

| 顺序 | 节点标识 | 界面名称 |
|------|----------|----------|
| 1 | `run_start` | 启动 |
| 2 | `project_manager_draft` | 项目经理起草 |
| 3 | `tester_testability` | 可测性 |
| 4 | `gate_requirement_confirm` | 需求确认 |
| 5 | `config_manager_plan` | 配置计划 |
| 6 | `ux_designer` | 体验 |
| 7 | `ui_designer` | 界面 |
| 8 | `visual_designer` | 视觉 |
| 9 | `project_manager_scope` | 范围 |
| 10 | `architect` | 架构 |
| 11 | `gate_architecture_review` | 架构评审 |
| 12 | `developer` | 开发 |
| 13 | `change_control` | 变更 |
| 14 | `code_reviewer` | 评审 |
| 15 | `tester_execute` | 测试 |
| 16 | `qa` | 质量门禁 |
| 17 | `project_manager_delivery` | 交付汇总 |
| 18 | `gate_final_delivery` | 最终交付 |
| 19 | `config_manager_closeout` | 收口 |
| 20 | `process_owner_retro` | 复盘 |
| 21 | `run_end` | 结束 |

`run_start` 与 `run_end` 只出现在轨道上，不进入可执行图，也不能被场景裁掉。尚未启动时当前格是「启动」，状态为「初始」。本轮完成后当前格是「结束」，状态为「结束」；此前会执行的格子为「完成」。这两格的箭头不流动。

`escalate_dev_retry` 不插入主路径。开发回退超限时，当前格变为「等待人工」，待办类型写「升级」。

财务角色定义保留在 `roles/finance/role.md`。三个财务节点在 `workflow.features.finance` 打开时进入主路径和轨道，默认不打开，此时轨道上不显示。

每一格同时只有一种状态，用文字标签区分，不只靠颜色：

| 状态 | 标签 | 何时 |
|------|------|------|
| 尚未到达 | 未到 | 在当前节点之后，且本轮会执行 |
| 不启用 | 不显示 | 在本轮 `skip_nodes` 里，或财务开关关闭 |
| 已完成 | 完成 | 已经离开该节点，且不是当前 `next` |
| 进行中 | 进行中 | `next` 指向它，阶段不是等待人工，也不是已暂停 |
| 已暂停 | 已暂停 | 人按下「暂停」，执行停在当前格，现场仍在 |
| 等待人工 | 待批复 | 阶段为等待人工，且关卡或澄清落在这一格 |
| 初始 | 初始 | 尚未启动，当前格是「启动」 |
| 最终 | 结束 | 本轮已完成，当前格是「结束」 |

尚未启动时只列出本轮会执行的节点。「启动」为当前格，标签为「初始」，其余格子为「未到」，箭头停在「启动」上且不流动。已完成时，「结束」为当前格，标签为「结束」，此前会执行的格子为「完成」，箭头停在「结束」上且不流动。已暂停时箭头停在被暂停的那一格，连线不流动。

不在页面上显示「完成几 / 本轮几」。

回退（测试失败回到开发、变更退回需求确认或架构评审）时，当前格改成被退回的节点，箭头改指这一格。已经走过的格子保留在列表里。返回箭头的画法见 5.1。

### 5.1 泳道

宽屏（约 900px 及以上）把这条主路径排成泳道，并在中栏宽度内一次看全，不出现横向滚动。泳道按角色拆开。各泳道共用一条水平刻度表示执行顺序：越早的格子越靠左，越晚的越靠右。刻度按容器宽度排布。同一泳道里的格子互不重叠。某一角色本轮没有格子时，整条不出现。裁掉的节点继续不画。

| 泳道 | 格子 |
|------|------|
| 人类 | 启动、需求确认、架构评审、最终交付、结束 |
| 项目经理 | 项目经理起草、范围、交付汇总 |
| 配置管理员 | 配置计划、收口 |
| UX 设计师 | 体验 |
| UI 设计师 | 界面 |
| 美工 | 视觉 |
| 架构师 | 架构 |
| 程序员 | 开发、变更 |
| 代码评审 | 评审 |
| 测试工程师 | 可测性、测试 |
| QA | 质量门禁 |
| 流程负责人 | 复盘 |
| 财务 | 预算粗估、预算、成本快照 |

人类泳道放在最上一行。其中三个关卡用黄底菱形岔路口标志表示需要人做选择，标志比普通节点图标大一半，活动名写在标志下方。关卡图标不代替中栏的批复表单。财务泳道仅在开关打开且本轮有财务格子时出现。相邻泳道用一深一浅两种背景区分，从第一行开始交替。

格子里写这一步的活动名。状态仍按本节用颜色区分，不把「完成」「进行中」写进格子。泳道名在每行左侧。除人类泳道固定写「人类」外，泳道名使用对应角色 `role.md` 的 `title`。

箭头只连接主路径上前后相邻的两格。连线从当前格的右侧引出，从下一格的左侧进入，拐弯用圆角。阶段为运行中时，只有指向当前格的那一段以虚线流动。发生回退、当前格落在已经走过的格子之前时，另画一条圆角返回箭头指向被退回的格子，流动的也改成这一段。等待人工、已暂停或已停止时，这段箭头停住并使用强调色。已结束时箭头停住，颜色与其他连线相同。

窄屏（约 900px 以下）不画泳道，退回单行：按主路径排成小按钮，一行放不下就换到下一行。点选、高亮和右栏检视与宽屏相同。

## 6. 人工处理页布局

保持现有三栏。

- 左栏：本轮标识，以及之后要补的 Run 列表。当前仍只有一轮时，列表里一项，空态写「尚未绑定」。
- 中栏：需求输入和人工待办保持现状。节点轨道放在待办上方，标题为「运行状态」，排法见 5.1。宽屏用泳道，窄屏退回单行。正在执行、等待人工、已暂停或已停止的当前格用强调色高亮，已完成的格子用灰色，尚未到达的格子用白色。指向当前格的连线用箭头标出；阶段为运行中时，这段连线以虚线流动，回退时这一段是返回箭头。点某一格，右侧改看这一步。人工待办容器与页面其他面板同一套底色和边框。「启动」只在尚未绑定或本轮已结束（已完成、已驳回、已停止）时可点。阶段为运行中或等待人工时，按钮变灰，文案改为「进行中」。同一行提供「暂停」和「停止」，直到本轮结束才收起。「暂停」只在运行中可点。停止会结束本轮，阶段变为已停止；正在执行的模型调用会被取消，若这次调用不能立刻返回，则在它结束后不再进入后续节点。暂停不结束本轮。
- 右栏：标题为当前节点的中文名。阅读方式见 6.2。原始 JSON 仍折叠，标题用「原始状态」。

关卡批复、澄清答复、升级选择仍用中栏已有表单。当前格不代替表单。

等待人工超过时限（默认 24 小时，可用 `AUTO_STUDIO_GATE_TIMEOUT_SECONDS` 覆盖）时，记一笔「超时未批复」。关卡仍停在原地，不自动批准或驳回。飞书卡片上的批复按钮不变。

状态更新：阶段为运行中或等待人工时，由服务端推送现有状态。已暂停时保留现场，不再推送；人按下继续并回到运行中之后，再恢复推送。阶段为已完成、已驳回或尚未启动时停止。请求未返回前不放转圈；轨道保持上一帧。读取失败时，需求输入下的错误行写「读不到这一轮的状态。检查服务是否还在，然后刷新。」轨道不清空。人离开页面即停止接收。页面上的阶段和错误文案不变。

动效：运行中的那一段箭头连线以虚线流动，周期约 1.1 秒。等待人工、已暂停、已停止或已结束时箭头停住。节点格子本身不播放位移动画。系统开启减少动态效果时，连线不流动。

### 6.1 暂停

暂停和停止是两件不同的事。停止结束本轮，阶段变为已停止，不能从原来的节点接着跑。暂停把这一轮留在原地：已完成的节点保持完成，当前格改为「已暂停」，阶段变为已暂停。现场、产物和 `thread_id` 都还在。

操作：

- 运行中：「暂停」与「停止」并列。暂停可点，停止仍可点。
- 已暂停：「暂停」换成「继续」。停止仍可点。「启动」保持不可用，避免另开一轮盖住现场。
- 等待人工：不提供暂停。这一轮已经停在关卡上，恢复方式仍是批复、澄清或升级选择。
- 已完成、已驳回、已停止、尚未启动：不提供暂停。

按下继续后，从被暂停的节点接着执行，不重做已经完成的格子。若暂停时模型调用还在进行，调用结束后不再进入下一节点，直到人按下继续。按下继续之后，从该节点重新进入执行。

文案：暂停成功后，待办上方写「本轮已暂停。已完成的节点不会重做。」继续之后这句消失，阶段回到运行中。暂停失败时写明原因，轨道保持暂停前的一帧。

飞书查询把阶段写为「已暂停」，当前行仍是这一格的中文名，待办写「无」。卡片不提供继续或停止。人要恢复，打开 Web。

### 6.2 右栏阅读

右栏顺序是：状态、摘要、会话、产物、调用次数、开发重试。

产物按份排成卡片，一份产物一张。标题用中文，例如需求说明、架构设计、测试报告。正文按 Markdown 排版：标题、段落、列表和表格用正文，代码块用等宽。卡片先显示一屏，其余收在卡片内。按钮写「展开全文」，展开后写「收起」。多份产物不再拼成一段，也不再截断前 400 字。全文来自这一轮落盘的产物；落盘没有这份文件时，用状态里的正文。

会话仍在产物之前，只读。助手回复按段落。工具调用收成一组。思考默认收起。运行中新步骤追加在这一节，不等节点结束。

调用次数和开发重试各占一行数字。成本账本原文不铺开。

## 7. 配置页

项目、运行、流程、配置和帮助共用同一套三栏。项目放最上面，二级菜单是「新建」「打开」和「从目录打开」。运行原名人工处理，二级菜单是新建 Run、运行状态、待办和当前轮次。运行状态就是一轮的泳道，不再叫「流程」，以免和一级菜单「流程」重名。流程页的二级菜单是「新建」和「打开」，编排方式见第 8 节。配置只保留与具体项目无关的共性项，按 Agent、工作区、飞书分成二级菜单。环境是只读清单，放在配置页右栏，不进左栏。字段种类不改。帮助放在配置下面，说明见第 8.1 节。

### 7.0 项目的新建与打开

「新建」和「打开」是同一份项目字段的两个入口。项目类型、通知不再各占一个二级菜单，改为主栏里的分组。右栏仍查看项目类型原文和合并结果，不进左栏。

主栏分组，自上而下：

1. 标识。新建时不手填，按标题自动生成。打开后只读，不能改已有项目的标识。
2. 说明。标题、说明、远程仓库、工作区。
3. 项目类型。项目类型、设计轨、节点裁剪。
4. 通知。飞书通知群、飞书通知人。
5. 其它。流程、开发重试上限。流程是下拉列表，选项为已保存的流程，可以不指定。
6. 原文。`project.yaml` 只在打开后可以覆盖。

新建：

- 地址是 `/project#new`。
- 字段从空白开始，可以直接填写。只写标题，不写项目标识。标题必填。
- 标识在按下「创建」时生成一次。名称本身已符合标识规则时原样保留，例如 `Demo_001`。其余英文名称整理成小写并用 `-` 连接。名称含中文时，先译成英文，再整理成标识，例如「预览流程」得到 `preview-workflow`。已有同名标识时，后面加 `-2`、`-3`。翻译失败时改用 `project-1` 这类序号，不因此取消创建。
- 创建后标识只读。以后修改标题，标识不变。
- 主按钮是「创建」。创建成功后进入打开，地址改为 `/project?project=<id>#open`，按钮下写「已创建项目 <id>。」
- 创建失败留在新建，按钮下写明原因。

打开：

- 地址是 `/project?project=<id>#open`。没有 `project` 时停在选择，不自动打开某一个。
- 先选择项目。未选时，其余字段不可编辑，选择框下写「先选择要打开的项目。」
- 还没有任何项目时，写「还没有项目。」旁边是「新建」，进入新建档。
- 主按钮是「打开」。按下后才载入该项目的字段，地址改为 `/project?project=<id>#open`。
- 项目已经打开后，「保存」是次要按钮。原文覆盖留在这一档。
- 换项目或离开这一档时，若字段已改且未保存，先问「放弃未保存的修改？」确认后才切换。取消则留在当前项目。

从目录打开：

- 地址是 `/project#from-directory`。
- 只填一个目录，必须是服务进程能读取的绝对路径。编辑框可以手填，右侧是打开文件夹按钮。选定目录后直接打开，不再另放「打开」。手填的路径按回车打开。目录列表里，鼠标所在的一行用底色和边框标出当前焦点。
- 打开已有项目时，若项目还没有远程仓库地址，且该仓库能解析出符合规则的远端地址，则写入项目。新建时同样写入。优先用 origin，没有 origin 时用第一个远端。
- 这个目录已经是某个项目的工作区：进入打开，并选中那个项目。多于一个项目指向同一目录时，先列出这些项目，人选定后再进入打开。
- 目录是 git 仓库，且还没有项目指向它：只补项目类型。项目标识按目录名自动生成，规则与新建项目相同；中文目录名会译成英文。项目类型必填。按钮是「创建并打开」。成功后进入打开，工作区就是这个目录。标题用目录名。
- 目录不存在、不是目录、不是 git 仓库，或是工厂仓库本身：留在这一档，按钮下写明原因，不创建项目。

进入「项目」时：地址带 `project` 就打开该项目；地址是 `#new` 就进入新建；地址是 `#from-directory` 就从目录打开；三者都没有时，已有项目则进入打开的选择态，没有项目则进入新建。这三档只放在左栏。「从目录打开」使用打开的文件夹图标。窄屏时左栏收成图标，这三档仍从左栏进入。

运行页仍只选择已有项目来启动，不在运行页新建项目。

运行页先选择项目，再填写交付目标。项目同一行有「Run 命名」，默认为项目标识加连字符和递增序号（如 `_example-1`），启动前可以改。项目类型只在项目配置里绑定一次，启动时沿用所选项目的 `scenario_key`，页面不再提供项目类型选择。

- 项目、项目类型、设计轨、节点裁剪、流程、后端、飞书后端用选择。流程列出已保存的流程，可以不指定。
- 标题、说明、远程仓库、重试上限、工作区、通知群、通知人、模型、默认工作区、Web 地址、API Key 用单行。远程仓库填 git 远端地址，可空，放在说明之下、工作区之上。项目工作区是待开发项目的 git 目录；留空时用运行配置里的默认工作区，默认工作区也留空时用 `workspaces/项目名`。
- `project.yaml`、`scenario.yaml` 和合并 JSON 只在「原文」里。
- 未选项目时，项目字段不可编辑。空态文案维持「先选择项目，或新建一个。」

### 7.1 凭证的连通测试

Agent 的 API Key，以及飞书后端选「应用凭据」时要写入的凭据，属于工厂级凭证。它们只出现在「配置」里，不进项目配置，也不出现在运行页。页面不回显已保存的密钥；环境列表只显示是否已配置。

按下「写入 .env」后，先保存，再对本次生效的凭证做一次连通测试。测试用当前选中的后端和模型。模型留空则按该后端的默认模型或自动路由测试。人这次没有改密钥时，用已经保存的值测试，输入框仍保持空白。密钥留空且从未配置时，不发起测试，环境列表保持「未配置」。

结果写在「写入 .env」下方，不弹新页：

- 已连通：写「已连通。」环境列表里对应项改为已配置。
- 连不上：写「连不上。」下一句说明原因和下一步，例如密钥无效、地址不可达或飞书应用凭据不匹配。已写入的值不自动删掉，避免一次探测失败把原配置清掉。
- 测试尚未返回：按钮保持忙碌，不重复提交。轨道和项目表单不受这次测试影响。

飞书后端选 lark-cli 时，不把应用密钥当必测项。连通测试改为确认本机 lark-cli 是否可用，结果仍写在同一处。默认工作区只检查路径是否可写，不把它当成凭证。

## 8. 飞书状态卡片

问句（整句去空白后）命中下列之一才算查询，不触发批准或驳回：`状态`、`到哪了`、`到哪`、`进度`、`status`。

回复一张卡片，四行，顺序固定：

1. 阶段：未启动 / 运行中 / 已暂停 / 等待人工 / 已完成 / 已驳回 / 已停止。
2. 当前：轨道上的中文名。没有运行时写「还没有进行中的轮次」。
3. 待办：无关卡时写「无」。有关卡时写待办类型和关卡中文名，例如「待批复 · 需求确认」。
4. 打开：Web 链接，带 `thread_id`。没有运行时省略此行。

卡片不附模型原文、不附完整成本账本。人要看产物，用链接回到 Web。

同一会话里若有多轮，卡片回答最近一轮仍在进行、已暂停或等待人工的；都已结束则回答最近一轮，并在阶段行写明已完成或已驳回。不在卡片里做选择器。已暂停的卡片不提供继续或停止。

## 8. 流程编排

流程页用来编写一份以后可以反复运行的流程。它和运行页上的泳道用同一套画法，但运行页只读，流程页可改。

左栏「流程」放在「运行」下面、「配置」上面。二级菜单只有「新建」和「打开」。主栏顶部不再重复这两档。窄屏收起左栏后，仍从左栏图标进入。

一份流程是活动、人类关卡、启动和结束的排列。活动按执行顺序从左到右。角色分成泳道，人类泳道在最上面。启动和结束放在人类泳道，是普通胶囊，不能删除，也不能跳过。人类关卡用岔路口图标，名称写在图标下面，并且只能留在人类泳道。活动名称写在节点里面。定义本身没有「完成」或「进行中」，那些状态只出现在运行页。

连线从节点右侧流出，从下一节点左侧流入，折角用圆角。回退从较晚的节点右侧绕回较早节点的左侧，不从上面或下面接入。同一泳道里的节点不重叠。没有活动的角色不占一条泳道。

角色名单来自 `roles/`。泳道和角色选择显示 `role.md` 的 `title`，与运行页泳道相同。换泳道只是把已有活动交给另一个已有角色，不能在这里新增角色，也不能改角色文件里的原则和默认产物。这个活动自己的输入、输出和模板写在节点上。节点裁剪仍留在项目或项目类型里，不写进流程定义。本页不能启动一轮。运行页以后再选择要用哪一份流程，这次不改运行页的启动表单。

地址：

- 新建是 `/workflow#new`。
- 打开是 `/workflow?workflow=<id>#open`。没有 `workflow` 时停在选择，不自动打开某一个。
- 进入「流程」时：地址带 `workflow` 就打开该流程；地址是 `#new` 就进入新建；都没有时，已有流程则进入打开的选择态，没有流程则进入新建。

标识与项目使用同一套生成规则。打开后标识只读。

新建：

- 画布上只有「启动」和「结束」，中间一条连线。
- 只写标题，不写流程标识。标题必填。
- 标识在按下「创建」时按标题生成一次。中文标题译成英文后再整理。重名时加 `-2`、`-3`。翻译失败时用 `workflow-1` 这类序号，不因此取消创建。创建后修改标题，标识不变。
- 主按钮是「创建」。成功后进入打开，地址改为 `/workflow?workflow=<id>#open`，按钮下写「已创建流程 <id>。」
- 创建失败留在新建，写明原因。

打开：

- 先选择流程。未选时画布不可编辑，选择框下写「先选择要打开的流程。」
- 主按钮是「打开」。按下后才载入该流程。
- 还没有任何流程时，写「还没有流程。」旁边是「新建」。
- 流程已经打开后，「保存」是次要按钮。原文默认收起，只在打开后可以覆盖。
- 换流程或离开这一档时，若已改且未保存，先问「放弃未保存的修改？」确认后才切换。取消则留在当前流程。

中栏标题是「编排」，样式与运行页的「运行状态」相同。

宽屏使用泳道。节点要保持能点中的宽度。节点多到一行放不下时，中栏可以横向滚动。运行页仍必须一眼看全、不横向滚动；编排页留出可点的目标，所以允许滚动。窄屏改为按执行顺序排列的单列，仍可选中、改顺序和删除，不把泳道挤成一团。

添加和修改：

- 「添加活动」先选择角色，再写活动名。角色列表第一项是「人类」。选人类时，这个节点成为人工关卡，名称写在岔路口图标下，并落在人类泳道。选其他角色时，新活动出现在「结束」之前，并落在该角色的泳道最右侧。新活动先带上该角色 `role.md` 里的输入和输出名字，模板留空，等选中后再补。
- 「添加关卡」同样进入人类泳道，位置在「结束」之前。决策点要选择决定类型，目前为「批准或驳回」。未选择决定类型的决策点不能启动。
- 点一个节点，右栏改看这一节点。点空白处，右栏回到流程说明。
- 活动和关卡都可以改名称和所属角色。所属角色一变，节点就换到对应泳道。改成人类时，节点成为人工关卡；改成其他角色时，关卡成为该角色的活动。启动和结束不能改名，也不能删除。
- 删除写在右栏，要再确认一次。删掉之后，前后节点按原来的先后重新连上。
- 沿水平方向拖动节点，松手后按从左到右重排。拖动不改变角色；换角色用右栏的选择。

右栏在没有选中节点时，自上而下是标识、标题和说明。选中活动时，自上而下是活动名、角色、输入、输出、前面和后面的节点。选中关卡时是决策点和前后节点。选中启动或结束时，只说明这两格不能删除、不能跳过。启动、结束和决策点没有输入、输出和模板。

宽屏时，右栏左缘有一条竖向分隔，可访问名称是「拖动调整检视栏宽度」。指针放上去变成左右调整。按住向左拖，右栏变宽、中栏变窄；向右拖则相反。宽度有下限，保证名称和模板地址还能读；也有上限，不超过视口一半，并给中栏留下可编排的宽度。松开后记住这次宽度。运行页和配置页的右栏使用同一宽度。焦点在分隔上时，左右方向键每次移动一小段。窄屏不显示这条分隔，右栏改到中栏下面。

活动的输入和输出：

- 输入、输出都在右栏显式列出，不把角色文件里的名单藏起来当作已经填好。角色文件只在新建活动时给一份初始名字。
- 每一项输入是一个产物名。可以手写，也可以从更早活动的输出里选。另外始终可以选「人类需求」，它不是某个活动的输出。同一活动里名字不能重复。列表从上到下，就是运行时交给这个角色的顺序。一项都没有时，写「这个活动不读取已有产物。」
- 每一项输出是一个产物名，并且必须带一份模板。同一活动里输出名字也不能重复，也不能和本活动的输入重名。一项都没有时，写「这个活动还没有输出。」
- 换角色时，若输入和输出仍是上一个角色带进来的初始名字、而且模板都还空着，就换成新角色的名字，模板继续空着。人已经改过名单或模板时，保持不动。
- 保存可以留下模板还没写完的草稿。启动一轮时，活动没有输出，或某项输出没有模板，就拒绝启动，并写明是哪一个活动、哪一项输出。

输出的模板：

- 模板正文不在这里编辑。每一项输出的地址栏上方标出「模板」，再二选一：本地文件，或一个链接。
- 本地文件是服务进程能读取的文件绝对路径。编辑框可以手填，右侧是选择文件。选定后把路径写入该项。路径不存在、不是文件，或进程读不到时，写在该项下面。
- 链接是 `http` 或 `https` 地址。写成别的形式时，写在该项下面。
- 同一项输出只保留当前选中的那一种。从「本地文件」改成「链接」，或反过来，清掉原来的地址。
- 模板用来约束这项输出的结构。运行时把模板交给该活动的角色，模型按模板写这项输出。

## 8.1 帮助

「帮助」是左栏最后一项一级菜单，放在「配置」下面。它只读。中栏显示说明，宽度跟随中栏，不另设窄栏。没有输入、保存或创建。右栏不放表单，只写「帮助只读。」宽屏仍保留右栏，避免从帮助回到其他页时中栏宽度跳动。窄屏收起左栏后，仍从左栏图标进入；右栏改到说明下面。

二级菜单只在「帮助」为当前页时展开，顺序固定：

| 顺序 | 菜单 | 地址 |
|------|------|------|
| 1 | 概览 | `/help#overview` |
| 2 | 入门指南 | `/help#guide` |
| 3 | 项目 | `/help#project` |
| 4 | 运行 | `/help#run` |
| 5 | 流程 | `/help#workflow` |
| 6 | 角色 | `/help#roles` |

点一级菜单「帮助」时，若地址没有上面的某一节，就进入概览，地址改为 `/help#overview`。点二级菜单只更换中栏这一篇，不询问是否放弃修改。当前这一节在左栏标成选中。未知的 hash 仍显示概览，并在标题下写「没有这一节，改看概览。」

中栏标题就是二级菜单的名字。正文按条目排列，每条仍是完整句子。不放操作按钮，也不复述字段的占位符。各篇条目如下。

概览：

- AutoStudio 接收人的交付目标，按项目绑定的流程让各角色写出文档和代码，并在决策点停下来等人批复。
- 工厂自身和待开发项目分开。
- 左栏自上而下是项目、运行、流程、配置和帮助。
- 项目决定这一轮用哪份流程、哪一种项目类型。运行看这一轮走到哪。流程编排活动和决策点。配置填写与具体项目无关的后端、工作区、飞书和环境。

入门指南：

- 安装完成后，先打开这个 Web 页面。
- 在「配置」的 Agent 中选择后端。想先熟悉界面，选 stub，它不调用 Cursor。
- 要让角色真正工作时，选 cursor，并写入 Cursor API Key。密钥只保存，页面不回显。模型可以留空，留空时使用 Auto。写完后按「写入 .env」。
- 工作区可以先空着。项目里填写的工作区优先于默认工作区。飞书可以以后再配。
- 在「项目」里新建项目，只写标题并选择项目类型。流程可以先不指定，这时使用内置的默认流程。
- 到「运行」，选择该项目，填写交付目标并启动。决策点在待办里批准或驳回。

项目：

- 可以新建、打开，或从本机的 git 目录创建。
- 新建只写标题。标识按标题生成，中文标题会译成英文。打开之后标识只读。
- 从目录打开时，标识按目录名生成，工作区就是这个目录。
- 项目里可以选择项目类型、设计轨、节点裁剪、通知对象、远程仓库、工作区和流程。流程可以不指定。

运行：

- 先选择项目，再填写交付目标并启动。名称默认是项目标识加递增序号，启动前可以改。
- 中栏是这一轮的泳道，只列出当轮会走到的节点。可以进行中暂停、继续或停止。
- 决策点、需求澄清和回退升级停在待办里，批复后继续。
- 点一个格子，右栏查看这一步的产物和该角色的会话。

流程：

- 可以新建或打开一份流程。新建只写标题，标识按标题生成。
- 宽屏用泳道排列活动和决策点。右栏左缘可以拖动。
- 活动要写出输入和输出。每项输出要有模板，模板是本地文件或 http、https 链接。
- 决策点目前的决定类型是批准或驳回。选进项目后，下一轮按这些节点执行。
- 活动没有输出，或某项输出没有模板时，不能启动。

角色：

- 角色写在工厂的 `roles` 目录里，每个角色一份 `role.md`。
- 页面不能新建角色，也不能改角色的原则。显示名用文件头里的标题。
- 新建活动时，用该角色文件中的输入和输出名字作为初值。模板仍要在流程页补上。

Agent：

- 在「配置」的 Agent 中选择后端。stub 不调用 Cursor。
- cursor 使用 Cursor SDK，并复用该工作区里已有的工具、规则和 Skill。
- 模型留空时使用 Auto。API Key 只写入本机配置，页面不回显。

工作区：

- 默认工作区在项目没有填写工作区时使用。
- 一轮任务在待开发项目自己的目录里进行，不改工厂仓库里的源码。
- 项目里填写的工作区优先于这里的默认值。

飞书：

- 飞书用来通知和批复，和网页上的待办是同一套决定。
- 可以填写飞书后端、卡片里的 Web 地址、默认通知群和默认通知人。
- 项目里另外填写的通知群或通知人优先于这些默认值。

环境：

- 配置页右栏按 Agent、工作区、飞书分成三组。每一项左侧是名称，右侧是是否已配置。有具体取值时写在名称下面。
- 密钥只显示已配置，不写出原文。
- 飞书命令行单独成组，安装、配置和发消息各占一行。说明按条目列在这组下面。

| 情境 | 轨道 | 主栏或状态条 |

| 尚未启动 | 不画格 | 「还没有运行记录。填写交付目标并启动后，阶段和产物会显示在这里。」 |
| 读取中，已有上一帧 | 保持当前这一格 | 「正在读取状态」 |
| 读取失败 | 保持当前这一格 | 「读不到这一轮的状态。检查服务是否还在，然后刷新。」 |
| 未知的 `thread_id` | 不画格 | 「没有这一轮。核对地址栏中的 thread_id。」 |
| 运行中 | 一格「进行中」 | 「启动」变灰，文案为「进行中」；旁边是「暂停」和「停止」 |
| 已暂停 | 停在被暂停的格，标签「已暂停」 | 「本轮已暂停。已完成的节点不会重做。」「继续」可点，「停止」可点 |
| 等待人工 | 一格「待批复」 | 中栏展开现有批复表单；「启动」仍为灰色的「进行中」，「停止」可点；不提供暂停 |
| 已完成 | 本轮会走的格均为「完成」 | 「这一轮已结束。右侧是最后一步的产物。」「停止」收起 |
| 已驳回 | 停在被驳回的关卡，该格标「待批复」且表单不再提交 | 「这一轮已驳回。」 |
| 已停止 | 停在被停止的节点，该格标「已停止」 | 「这一轮已停止。」「启动」恢复可点 |
| 场景跳过 | 当前节点不会是被跳过的格 | 无额外句子 |

按钮和错误沿用现有说法：保存、创建、取消、提交并续跑、暂停、继续、停止。凭证测试的结果用「已连通」或「连不上」。错误写明原因和下一步，不用感叹句。计数用阿拉伯数字。

## 10. 无障碍与实现约束

- 轨道是一行可横向滚动的小按钮。当前格用 `aria-current` 和按钮名称里的状态文字暴露给读屏，不单靠颜色。
- 点某一格，右侧检视改看这一步；再点当前正在执行的格，检视回到这一步。
- 阶段胶囊使用礼貌的实时区域，阶段变化时读出新标签，不打断输入。
- 对比度沿用现有浅色与深色令牌。深色背景保持现在的近黑，正文不用纯白。
- 不新增图标库。主栏阶段仍用文字标签。左栏运行列表的阶段和删除用图标，名称和阶段写在可访问名称里。运行中是转圈并旋转，已停止是方块，等待人工是三角感叹号。系统开启减少动态效果时转圈停住。确认删除仍用文字。
- 悬停只改变背景，且仅在有鼠标的设备上。触控点击区域不小于 44px。
- 不使用会带动布局的动画。减少动效时去掉透明度过渡。

## 11. 尚未决定

- Run 列表来自检查点。左栏标题为「Run列表」，可按阶段筛选，其中「全部」列出已有轮次。点进一轮仍用现有轨道和 `thread_id`。每一行的阶段和删除是图标，悬停可读出阶段和名称；确认删除仍要再点一次文字按钮。后返回的旧筛选结果不能盖住当前选择。
- 轮询 2 秒是否在长任务上过于频繁。若服务端推送更容易接在现有运行服务上，实现时可以替换，界面文案不变。
- 飞书上「最近一轮」以本聊天绑定为准，还是以项目配置里的通知对象为准。实现前需要定一条，避免同一群里答错轮次。
