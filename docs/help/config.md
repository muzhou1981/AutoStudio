# 配置

配置页填写与具体项目无关的共性设置：Agent 后端和飞书。设置写入工场根目录的 `.env`，只保存在本机。右栏的“环境”只读列出各项是否已配置。

## Agent {#agent}

| 字段 | 说明 |
|------|------|
| 后端 | `stub` 不调用外部模型，用来熟悉界面；Cursor SDK 复用工作区里已有的工具、规则和 Skill；Codex SDK 在目标工作区里读写文件并执行命令。 |
| API Key | 按“添加密钥”写入，文字随后端变化。先校验有效再写入本机 `.env`，页面不回显原文；“删除”移除已保存的密钥。`stub` 不需要填写。 |
| 默认模型 | 角色没有为本轮另选模型时使用。留空时使用后端自己的默认模型。 |
| Codex 推理强度 | 只在后端为 Codex SDK 时出现。可选级别随所选模型读取。 |
| MCP | 只读列出所选后端会加载的 MCP 服务器，对所有角色可见。 |

修改后按“写入 .env”。页面随后检测连通性，并在按钮下方写出结果。

> [!NOTE]
> Codex 可以不写密钥，直接使用启动服务的同一系统用户已登录的 Codex 账号。写了 OpenAI API Key 时，优先使用密钥。

MCP 服务器的增删不在这里进行：

- Cursor SDK 读取工作区与用户目录下的 `.cursor/mcp.json`，在 Cursor 的 MCP 设置里修改。
- Codex SDK 读取 `~/.codex/config.toml` 的 `mcp_servers`，修改该文件。

每一轮还可以在运行页为单个角色选择模型、推理强度、Fast 和上下文长度，优先于这里的默认值。见[启动一轮](run.md#start)。

## 工作区 {#workspace}

工作区是待开发项目的 git 目录，在[项目](project.md#fields)里填写。

- 一轮用哪个目录，按以下顺序确定：项目里填写的工作区；`.env` 中的 `GENI_STUDIO_TARGET_ROOT`；工场目录下的 `workspaces/<项目标识>`。
- 每一轮在工作区里另开一个工作树和分支 `geni-studio/<Run 标识>`，不直接改当前分支；流程含“提交入库”时，批准后合并回开工时的分支。少数流程（例如内置的“自我改进”）直接在当前分支上工作，同一仓库同时只能有一轮。改动存放的位置、何时入库与并行注意事项，见[代码在哪里](run.md#workspace)。
- 本轮产物和附件存放在工作区的 `.geni_studio/runs/<Run 标识>/` 下，该目录已加入 `.gitignore`。
- 运行期间，工场会禁止从本轮工作树推送到远端；本轮结束后自动解除。

## 飞书 {#feishu}

飞书用来发通知和批复，与网页上的人工待办是同一套决定：在任一处处理后，另一处同步更新。

| 字段 | 说明 |
|------|------|
| 飞书后端 | “lark-cli”使用本机 `lark-cli` 的登录；“应用凭据”使用 `.env` 中的应用标识和应用密钥。 |
| Web 地址 | 卡片里“打开”链接指向的地址，写成实际打开页面的地址。 |
| 默认通知群 | 群的 `chat_id`，形如 `oc_…`。项目没有填写通知群时使用。 |
| 默认通知人 | 飞书用户的 `open_id`，形如 `ou_…`，不是 Agent 后端的名称。 |

项目里填写的通知群或通知人优先于这里的默认值。决策点的飞书卡片列出待审阅的内容；带决策项时，卡片只给出摘要，逐项审批请按卡片上的按钮回到网页处理。

> [!WARNING]
> 要在飞书里点按钮批复，需要在飞书开放平台为应用订阅 `card.action.trigger` 回调。完整的接入步骤见仓库的 `docs/install.md`“接上飞书”一节。

## 环境 {#env}

配置页右栏的“环境”按 Agent、工作区、飞书分组，只显示每一项是否已配置：

- 每一项左侧是名称，右侧是状态。有具体取值时写在名称下面。
- 密钥只显示“已配置”，不写出原文。
- “飞书命令行”单独列出 `lark-cli` 的安装、配置和发消息检查结果。

通过本页保存的设置立即生效，新一轮按新设置执行。直接用编辑器修改 `.env` 文件后，需要重启 GeniStudio 服务才会生效。
