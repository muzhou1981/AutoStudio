# 项目

项目代表一个待开发的软件。它决定每一轮在哪个目录里工作、按哪份流程执行、通知发给谁。左栏“项目”下有“新建”“打开”和“从目录打开”三种进入方式。

## 新建项目 {#new}

1. 在左栏选“项目”→“新建”。
2. 写“标题”，需要时补一句“说明”。
3. “工作区”按右侧的目录按钮选择待开发项目的 git 目录，也可以留空。
4. 在“流程”里选定一份流程。没有流程时，先到[流程](workflow.md#create)页创建。
5. 按“创建”。页面提示“已创建项目”及项目标识后，进入这个项目。

> [!NOTE]
> 标识按标题自动生成，中文标题会译成英文。创建后标识不再改变，之后修改标题也不影响标识。

## 从已有目录创建 {#from-directory}

1. 在左栏选“项目”→“从目录打开”。
2. 在“目录”里填写服务进程能读取的 git 目录绝对路径，或按右侧按钮选择。手动填写时按回车。
3. 这个目录已属于一个项目时，直接打开那个项目；属于多个项目时，列出它们供选择。否则选择流程，按“创建并打开”。

这样创建的项目，标识按目录名生成，工作区就是这个目录。

## 打开与修改 {#open}

- 在左栏选“项目”→“打开”，从“选择项目”里选一个。
- 修改后按“保存”。标识只读。
- 按“删除”并确认后，永久删除工场里的项目定义（`projects/<标识>/`），不能恢复。待开发项目目录里的文件不受影响。

## 字段说明 {#fields}

| 字段 | 说明 |
|------|------|
| 标题 | 页面和 Run 列表中显示的名称。 |
| 说明 | 一句话描述，可空。 |
| 工作区 | 待开发项目的 git 目录，可空。规则见[工作区](config.md#workspace)。 |
| 飞书通知群 | 群的 `chat_id`，形如 `oc_…`，可空。 |
| 飞书通知人 | 用户的 `open_id`，形如 `ou_…`。通知群为空时使用。 |
| 流程 | 必须选定一份。下一轮起按这份流程执行。 |
| 开发重试上限 | 开发活动最多重试几次，填整数。留空时使用默认值。 |

项目里填写的通知群或通知人优先于配置页的默认值。

## 工作区的要求 {#workspace-rules}

- 工作区必须是目录，不能是文件。
- 目录非空时，必须已经是 git 仓库；空目录会在第一轮启动时初始化。
- 本地仓库的克隆与拉取由人自行完成，工场不代为执行。
- 仓库处于分离头指针（detached HEAD）状态时不能启动，先切回一个命名分支。
