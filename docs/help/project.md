# 项目

项目代表一个待开发的软件。它决定每一轮在哪个目录里工作、按哪份流程执行、通知发给谁。左栏“项目”下有“新建”“打开”和“从目录打开”三种进入方式。

## 新建项目 {#new}

1. 在左栏选“项目”→“新建”。
2. 在“基本信息”里写“标题”，需要时补一句“说明”。
3. 在“流程与执行”里选定一份流程。没有流程时，先到[流程](workflow.md#create)页创建。
4. 在“工作区”里按目录按钮选择待开发项目的 git 目录，也可以留空。
5. 按“创建”。标题或流程没填时，错误写在对应字段下方。页面提示“已创建项目”及项目标识后，进入这个项目。

> [!NOTE]
> 标识按标题自动生成，中文标题使用 `project-1` 这类序号。创建后标识不再改变，之后修改标题也不影响标识。

## 从已有目录创建 {#from-directory}

1. 在左栏选“项目”→“从目录打开”。
2. 在“目录”里填写服务进程能读取的 git 目录绝对路径，或按右侧按钮选择。手动填写时按回车。
3. 这个目录已属于一个项目时，直接打开那个项目；属于多个项目时，列出它们供选择。否则选择流程，按“创建并打开”。

这样创建的项目，标识按目录名生成，工作区就是这个目录。

## 打开与修改 {#open}

- 在左栏选“项目”→“打开”，从“选择项目”里选一个。
- 修改后按“保存”。标识只读。有未保存的修改时，换项目、去其他页面或关闭页面前会先询问。
- 按“删除”并确认后，永久删除工场里的项目定义（`projects/<标识>/`），不能恢复。已结束的 Run 记录与待开发项目目录里的文件不受影响。
- 项目还有未结束的 Run（运行中、等待人工、已暂停、已中断）时不能删除。页面列出这些 Run，先停止它们或等它们结束。
- 右栏“项目概览”列出流程、实际使用的工作区与代码的落地方式、最近的 Run，以及代码还没回到项目目录的 Run。
- 更换工作区时，若原工作区里还有未结束的 Run，或已结束但改动没有合并回来的 Run，工作区下方会列出它们。这些 Run 的改动仍留在原目录，新的 Run 在新目录开始。

## 字段说明 {#fields}

| 字段 | 说明 |
|------|------|
| 标题 | 必填。页面和 Run 列表中显示的名称。 |
| 说明 | 一句话描述，可空。 |
| 流程 | 必填。下一轮起按这份流程执行。 |
| 开发重试上限 | 开发活动最多重试几次，填不小于 0 的整数。留空时沿用流程的设定，流程也未设定时为 3。 |
| 工作区 | 待开发项目的 git 目录，可空。下方说明留空时实际使用的目录，以及所选流程是为每一轮建立工作树，还是直接修改当前分支，详见[代码在哪里](run.md#workspace)。规则见[工作区](config.md#workspace)。 |
| 飞书通知群 | 群的 `chat_id`，形如 `oc_…`，可空。规则见[通知发给谁](#notify)。 |
| 飞书通知人 | 用户的 `open_id`，形如 `ou_…`，可空。通知群为空时使用。 |

## 通知发给谁 {#notify}

项目的通知群与通知人作为一组，整体覆盖配置页的默认通知群与默认通知人，不逐项合并：

- 两项都留空：使用配置页的默认值。配置页也没有填写时，不发飞书通知。
- 只要填写了其中一项：只使用项目的设置，配置页的默认值不再生效。例如项目只填通知群时，配置页的默认通知人收不到通知。
- 每次只发给一个对象，通知群优先：填写了通知群就只发到群，通知群为空时才发给通知人。配置页的默认值同样如此。

| 项目通知群 | 项目通知人 | 实际发给 |
|------|------|------|
| 空 | 空 | 配置页的默认通知群；默认通知群为空时，发给默认通知人 |
| 空 | 已填 | 项目通知人 |
| 已填 | 空或已填 | 项目通知群 |

## 工作区的要求 {#workspace-rules}

- 工作区必须是目录，不能是文件。
- 目录非空时，必须已经是 git 仓库；空目录会在第一轮启动时初始化。
- 本地仓库的克隆与拉取由人自行完成，工场不代为执行。
- 仓库处于分离头指针（detached HEAD）状态时不能启动，先切回一个命名分支。
