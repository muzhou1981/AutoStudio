# 角色

角色定义一类 Agent：负责什么、遵循什么原则、读写哪些产物、能否读写文件和运行命令。流程里的每个活动都由一个角色执行。左栏“角色”下有“新建”和“打开”。

## 新建角色 {#new}

1. 在左栏选“角色”→“新建”。
2. 写“标题”，按“创建”。标识按标题自动生成，中文标题使用序号，创建后不再改变。
3. 在下方补齐类别、职责、输入、输出、能力和原则与价值观，按“保存”。

## 修改与删除 {#edit}

- 在左栏选“角色”→“打开”，从“选择角色”里选一个即可编辑。最上方的选择框仍可切换到其他角色。
- 修改后按“保存”。离开页面前有未保存的修改时，会先询问是否放弃。
- “删除”只对没有被任何流程使用的角色有效。要删除已被使用的角色，先从那些流程里去掉它的活动。

## 字段说明 {#fields}

| 字段 | 说明 |
|------|------|
| 标题 | 泳道和流程画布上显示的名称。 |
| 类别 | “执行角色”负责产出；“管理角色”负责评审、把关与协调。 |
| 职责 | 逐条写这个角色负责的事。 |
| 输入 | 这个角色通常读取的产物，从工厂已有的产物名里选择，可以为空。 |
| 输出 | 这个角色通常写出的产物，从工厂已有的产物名里选择。 |
| 能力 | 读取文件、写入文件、运行命令。都不勾选时，这个角色只写文字。 |
| 原则与价值观 | 角色的工作准则，运行时交给模型作为行为约束。 |

> [!NOTE]
> 角色的输入和输出只是新建活动时的初值。每个活动实际读写什么、用哪份模板，以流程里的设置为准。

## 内置角色 {#builtin}

| 角色 | 类别 | 主要职责 |
|------|------|------|
| 项目经理 | 管理 | 澄清需求、写验收标准，汇总产物并提交交付报告，是工场与人沟通的统一渠道。 |
| 架构师 | 管理 | 依据需求写架构设计，拆分任务计划。 |
| UX 设计师 | 执行 | 梳理用户目标与任务路径，写体验设计说明。 |
| UI 设计师 | 执行 | 写界面与组件规格。 |
| 美工 | 执行 | 制作并交付图标、插图等视觉资源。 |
| 程序员 | 执行 | 按任务计划实现代码，补单元测试，根据反馈修复。 |
| 代码评审 | 管理 | 对照设计审查代码变更，给出通过或需修改的结论。 |
| 测试工程师 | 执行 | 设计并执行测试，写测试报告。 |
| QA | 管理 | 对照验收标准独立验收，给出能否交付的结论。 |
| 合规管理 | 管理 | 审查隐私、网络安全和知识产权风险，不代替 QA 的交付结论。 |
| 配置管理员 | 管理 | 制定配置管理计划，维护基线与模板。 |
| 财务 | 管理 | 估算预算，跟踪花费并预警。 |
| 流程负责人 | 管理 | 每轮结束后复盘流程与角色，提出改进提案。 |

人类不是可管理的角色。决策点只能放在流程的人类泳道里，不在这个列表中。
