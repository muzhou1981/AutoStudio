# 常见问题

按现象查找。每一条先写可能的原因，再写处理办法。

## 按“启动”后报错 {#start-failed}

先看“启动”按钮上方的红色提示，常见的有：

- **工作区不是 git 仓库**：工作区目录非空但不是 git 仓库。换一个已有仓库，或改用空目录。
- **处于分离头指针**：待开发项目仓库没有处在命名分支上。在仓库里切回一个分支后重试。
- **流程有待补项**：到[流程](workflow.md#check)页查看“运行前待补”，补齐后保存。
- **目标项目已有写入进行中**：同一目录上一轮没有正常结束，写入锁仍被占用。等那一轮结束；确认持有锁的进程已不存在时，重启 GeniStudio 服务。
- **密钥无效或未配置**：到[配置](config.md#agent)检查后端和 API Key。

## 启动后长时间没有进展 {#stuck}

- 看泳道里当前的格子，点开它查看右栏会话是否仍在更新。真实模型执行一个活动可能需要数分钟。
- 右栏顶部写“本轮等待人工”时，这一轮在等人处理，见[处理人工待办](run.md#todo)。
- 显示“中断”时，服务曾经中断。按“续跑”从中断的节点接着做。

## 页面显示与预期不一致 {#stale-page}

- 服务升级后页面仍像旧版：按 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd> 强制刷新。
- 人工待办没有出现：在待办区按“刷新状态”。

## 收不到飞书通知 {#feishu}

- 配置页“环境”里查看“飞书命令行”的检查结果，确认 `lark-cli` 已安装并完成配置。
- 从桌面、IDE 或系统服务启动 GeniStudio 时，进程可能找不到 `lark-cli`。在 `.env` 设置 `GENI_STUDIO_LARK_CLI_PATH` 为它的绝对路径，然后重启服务。
- 确认项目或配置页里填写了通知群或通知人，且格式正确：群以 `oc_` 开头，人以 `ou_` 开头。项目里只填了其中一项时，配置页的默认值不再生效；同时填了群和人时只发到群。见[通知发给谁](project.md#notify)。
- 能收到通知、但点卡片按钮没有反应：飞书开放平台没有为应用订阅 `card.action.trigger` 回调。

## 决策点批错了怎么办 {#wrong-decision}

已提交的决定不能撤回。批准错了时，可以在后续的决策点选不通过，退回需要重做的活动；也可以停止本轮，用 Run 列表的“复制”新开一轮。

## 不通过后，退回的活动知道要改什么吗 {#reject-feedback}

知道。不通过时填写的附言，以及逐项审批里每一项“不通过的原因”，都会作为“需要修复的问题”交给退回的活动。附言写得越具体，重做越准确。

## 删除 Run 会删掉代码吗 {#delete-run}

项目目录当前分支上的文件不受影响，已提交到本轮分支 `geni-studio/<Run 标识>` 且尚未合入的内容也会保留。但删除 Run 会移除本轮工作树，其中尚未提交的改动随之删除。详见[删除 Run 时](run.md#workspace-delete)。

## 能否同时运行多轮 {#parallel-runs}

可以。每一轮在独立的工作树和分支上工作，互不阻塞。直接在当前分支上工作的流程（例如“自我改进”）例外：同一仓库同时只能有一轮。各轮看不到彼此尚未入库的改动，入库有先后，注意事项见[同时运行多轮](run.md#workspace-parallel)。

## 更多排障信息 {#more}

仓库的 `docs/install.md`“运行期排障”一节写有命令行排查方法，面向部署和维护 GeniStudio 的管理员。
