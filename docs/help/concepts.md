# 核心概念

GeniStudio 把一次交付拆成三层：项目说明做什么、在哪里做；流程说明按什么顺序、由谁来做；Run 是按流程实际执行的一轮。

## 三个层次 {#layers}

- **项目**：一个待开发的软件。它记录工作区（待开发项目的 git 目录）、飞书通知对象，并且必须选定一份流程。
- **流程**：一张由节点和连线组成的图，规定每一轮按什么顺序做什么。一份流程可以被多个项目选用。
- **Run**：项目按它的流程执行的一轮。每一轮有自己的交付目标、名称、产物和决定记录，彼此互不影响。

工场仓库与待开发项目分开存放。Run 只改待开发项目，不改工场自身的源码。

## 术语表 {#glossary}

| 术语 | 含义 |
|------|------|
| 交付目标 | 启动一轮时写下的要求，是这一轮所有角色工作的起点。 |
| 角色 | 一类 Agent 的定义：职责、原则与价值观、读写哪些产物、能否读写文件和运行命令。 |
| 活动 | 流程中由某个角色完成的一步，读取输入产物，写出输出产物。 |
| 产物 | 活动之间交接的文档或代码，例如需求说明、设计文档、测试报告。 |
| 模板 | 约束某项输出结构的文件或链接。每项输出都要有模板。 |
| 决策点 | 流程中停下来等人批复的节点。泳道和画布上用方框图标表示，批复后框内打勾。 |
| 决策项 | 决策点里需要逐条核对的条目，每条给“通过”或“不通过”。 |
| 不通过时 | 决策点不批准时的去向：退回到某个活动重做，或结束本轮。 |
| 回退 | 活动的结果没有达标时，自动回到更早的活动重做，次数受“最多循环”限制。 |
| 回退升级 | 回退次数用尽后交给人决定：继续再跑一次、暂停保留现场，或终止本轮。 |
| 需求澄清 | 角色认为交付目标不够清楚时提出的问题，答复后继续。 |
| 并行 | 同时执行的几条支路，在汇合处合并改动，或写出对照交给人选择。 |
| 子图 | 被别的流程当作一个节点引用的流程，用来复用一段固定步骤。 |
| 人工待办 | 运行页右栏下方等人处理的事项：决策点、需求澄清和回退升级。 |
| 工作区 | 待开发项目的 git 目录。每一轮在其中另开工作树和分支，不直接改当前分支。 |
| 后端 | 驱动角色执行的 Agent SDK：`stub`、Cursor SDK 或 Codex SDK。 |
| Skill 与 MCP | 角色可以使用的扩展能力。Skill 按节点为本轮选择；MCP 是全局配置，对所有角色可见。 |

## 一轮是怎样推进的 {#lifecycle}

1. 在运行页选定项目，写交付目标，按“启动”。
2. 流程从“启动”节点开始，依次执行活动。每个活动由对应角色读取输入、写出输出。
3. 遇到需求澄清、决策点或回退升级时，这一轮停下来，在人工待办里等人处理。配置了飞书时，同时发出通知。
4. 人处理后，这一轮从停下的地方继续，直到“结束”节点，或在某个决定处结束。

运行中可以暂停、继续或停止。服务中断后，可以从中断的节点续跑，已完成的节点不会重做。详见[运行](run.md)。
