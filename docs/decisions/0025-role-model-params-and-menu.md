# 0025 · 角色模型参数的通用映射与模型菜单

- 状态：已实现
- 日期：2026-11-12
- 关联：[0020](0020-role-session-per-run-and-cursor-settings.md)（角色会话与 Cursor 设置）、[0023](0023-role-fast-mode.md)（Fast 模式）。

## 背景

1. Cursor 模型目录（`Cursor.models.list`）中，48 个模型里有 22 个声明了参数 `context`（如 Claude Opus 5.5 为 `300k`/`1m`，GPT-5.5 为 `272k`/`1m`），此前运行页不读取也不传递，只能用模型默认的上下文长度。
2. 目录以变体（`variants`）列出允许的参数组合，并非都是全组合：GPT-5.5 与 GPT-5.4 的 `1m` 上下文不能与 `fast=true` 同用，而两者默认上下文就是 `1m`。只校验显式选择时，单独打开 Fast 会在服务端按默认补齐成目录外的组合。
3. 右栏「角色属性」原为模型、推理强度、Fast 三个并排的下拉框，再加一项会更拥挤；Cursor IDE 的模型菜单以一枚摘要加弹出菜单承载同类设置。
4. 推理强度与 Fast 是两个后端都有的语义（Codex 分别映射为 `reasoning_effort` 与 `service_tier`），上下文长度只存在于 Cursor 目录。

## 决定

1. **通用参数映射。** 图状态 `FactoryState` 新增 `role_model_params: dict[str, dict[str, str]]`（角色到「参数名 → 取值」），承载推理强度与 Fast 之外、由模型目录声明并开放选择的参数；开放名单为 `reasoning.MODEL_PARAMS`，目前只有 `context`，`thinking`、`cyber` 等不开放。推理强度与 Fast 保持各自字段，不并入映射，以免改变 Codex 的映射与已保存 Run 的格式。草稿、启动、运行中修改（`PUT /api/runs/{id}/role-models` 的 `role_model_params`）与复制 Run 均携带。
2. **目录行。** Cursor 目录行新增 `params`（开放参数的取值、显示名与默认值）与 `variants`（只含开放参数、推理参数与 `fast` 的允许组合，去重）；组合是全组合或变体未逐项列出时不下发，表示不限制。
3. **组合校验与补齐。** 页面与后端都按 `variants` 校验：与显式选择冲突的取值禁用；显式选择允许、但与沿用默认的项拼起来越界时，页面把需要变动的默认项改为离默认最近的允许取值并写成本轮选择，同时说明；后端调用前再次校验，越界报错，按默认补齐会越界时显式传入补齐值。
4. **模型菜单。** 「角色属性」改为一枚摘要（模型、推理强度、上下文、开启时的 Fast，沿用默认的项浅色显示），点开为两层菜单：首页 Fast 开关、上下文、推理强度、模型；指针或焦点移到某项时，取值列表作为子菜单在首页旁弹出（优先右侧，放不下改左侧，不遮挡首页），模型子菜单带搜索。子菜单挂在 `document.body` 上并以固定定位放置，因为设置区声明了 `container-type`，会成为固定定位元素的包含块。菜单状态（弹出的子菜单、搜索词、焦点是否在搜索框）记在页面变量中，右栏重绘后恢复。
5. **会话标识。** 开放参数的取值进入 Cursor 会话标识，改动后从该角色下一次调用起换用新会话，与推理强度、Fast 相同。
6. **参数随模型记忆。** 与 Cursor IDE 一样，推理强度、Fast 与开放参数按模型保存：显式改动其中一项时记下当前模型的取值；换模型时换上新模型上次的取值，没记过的回到默认，不再把旧模型的取值带到新模型。换走时不记旧模型，以免 Run 里沿用下来、没被改过的取值覆盖别处记下的选择。按「角色 → 后端:模型」稀疏保存，只记有过选择的模型，全部沿用默认时删去该项；数据量为角色数乘以用过的模型数，每项至多三个短值。按角色而不是按模型全局记忆，因为同一模型在不同角色上常需不同的推理强度，而各角色的设置本来就分开保存。
7. **记忆存在服务端用户配置。** 为在多台机器间共用并为日后的 CLI 入口留出接口，记忆写入服务端的用户配置文件 `user_config.json`（`geni_studio.config.user_prefs`），不放浏览器：
   - 位置：`GENI_STUDIO_USER_CONFIG_PATH` 优先，否则与检查点库同目录（默认 `runs/user_config.json`）；预览实例的检查点在 `.geni_studio/preview/`，因此自动与主服务隔离。
   - 格式：`{"version": 1, "role_model_prefs": {角色: {"后端:模型": {effort, fast, params}}}}`；文件中的其它键原样保留，供以后加入别的用户偏好。取值沿用 Run 设置的校验（角色标识、推理强度、Fast、开放参数）；读取时丢弃无法识别的条目，整份无法解析时报错而不覆盖。
   - 接口：`GET /api/config/user/role-model-prefs` 读取全部记忆；`PUT` 同一路径逐项写入一个角色在一个模型上的取值，空值删去该项。逐项写而不是整份覆盖，多台机器同时改不同的项互不吞掉；写入在进程内加锁并以临时文件替换落盘。CLI 可直接调用 `role_model_prefs()` 与 `set_role_model_pref()`。
   - 页面持有一份副本，改动逐项写回，刷新角色设置时重新读取，以便看到其它机器或 CLI 的改动；读取期间页面又改过时以页面副本为准。早先存于浏览器 `localStorage`（键 `geni_studio_role_model_prefs`）的记忆在首次读取时补写到服务端，随后删除本地副本。
   - 不放进 Run 状态：Run 只保存当前模型实际生效的取值，后端与调用不变；记忆只决定换模型时的预填值。
   - 用户配置目前按服务划分，不区分操作者：本服务只有一个访问令牌与一个操作者名（`GENI_STUDIO_WEB_OPERATOR`）。日后支持多名操作者时，在同一文件内按操作者分节。

## 后果

- 右栏两组始终并排、平分宽度，角色组不再分栏；窄屏不再需要两组上下排列的断点。
- 参数记忆跟随服务：从任何机器打开同一服务都能恢复；换一台服务或删除 `user_config.json` 后回到默认，已保存的 Run 不受影响。
- 新建 Run 时角色的初始模型不套用记忆，只有在菜单里换模型时才恢复；如需新 Run 也按记忆预填，另行处理草稿与默认值的读取顺序。
- Codex 后端没有可选的上下文档位，菜单不显示这一项；若日后 Codex 目录提供，再映射到 `role_model_params`。
- 后续开放其它目录参数时，只需加入 `MODEL_PARAMS` 并为其补充中文标题，不再新增状态字段与接口参数。
