# 0031 · 并行支路补齐与两路对照

- 状态：已接受；2.1、2.2 已实现，2.3 待进行
- 关联：补充 [0006](0006-subgraph-parallel-and-reject-target.md) 的并行与 [0016](0016-parallel-worktrees-and-lock-scope.md) 的支路工作树。

## 1. 背景

1. 需求（`docs/requirements.md`）把并行分为两种：同一份方案由两路分别实现、用来对照；一个子系统拆成几个模块并行开发。现有实现只覆盖后一种。
2. `_validate_parallel` 拒绝支路里出现决策点、回退、条件去向、内置后处理与嵌套并行。内置「大语言模型整网适配或推理框架适配」的支路插入了「NPU 算子开发」子图，子图里有决策点「确认 CCA」「确认 AOM」，因此这份内置流程目前**不能启动**，流程页的可运行检查也如此提示。
3. 两路实现同一方案时，改动必然落在相同文件上。现在汇合时按 ADR 0016 依次把各支路差异三方合并回本轮工作区，两路对照必然产生冲突并升级给人，得不到「对照后择一」的效果。
4. 状态里与支路相关的通道已按键合并（`return_counts`、`return_decisions`、`branch_artifacts`、`branch_workspaces`），支路内回退的执行代码已有雏形，只是被校验拦下；决策点的通道（`gate_decision`、`last_gate_decision`）与待办（`awaiting_human`，约 30 处引用）都按「同一时刻只有一个待决」设计。

## 2. 方案

### 2.1 支路内回退（第一步）

- 允许支路内的活动写 `returns_to`，目标必须在同一支路内、且在它之前；越出支路的目标在校验时拒绝。
- 回退反馈按支路记：写在 `branch_artifacts` 的保留键 `<并行>:<支路>:__return_feedback__` 下（状态定义在人工维护的 `default.py`，不为此新增通道），被退回的活动从这里读「需要修复的问题」，本支路有活动通过后清空；汇合时跳过这个键，不当作产物。不写全局 `return_feedback`，避免两路互相覆盖。
- 判定类活动每次执行都写自己的 `return_decisions`（通过时为空串）。该通道按键合并，只在未通过时写会把上一次的回退去向留下，路由会再次退回。
- 编辑器在并行的右栏、支路里每个活动下方提供「未通过时回到」（同一支路里更早的活动）与「最多 N 轮」；保存时校验目标在同一支路且更早。
- 回退次数用完时，该支路停在升级：其余支路照常跑完，汇合节点发现有升级就不再往下走（`_join_route` 已有此判断），本轮停下等人；人选择「继续」时只重做该支路的回退目标（沿用 ADR 0028 的「继续即重做一次」）。

### 2.2 两路对照（第二步）

- 并行节点新增 `join`：`merge`（默认，即现有行为）或 `compare`。编辑器在并行节点的设置芯片里提供「汇合方式：合并 / 对照择一」。
- `compare` 的汇合不合并代码：保留各支路工作树，生成产物 `branch_comparison`，逐路列出产物摘要、改动文件与增删行数，以及各路判定类活动的结论（若有）。
- 择一由紧随汇合的一个**选择**完成，见第 3 节取舍。选定后把该支路差异合并回本轮工作区、同名产物取该支路的版本，删除全部支路工作树；未选中的支路改动保留为补丁文件（`runs/<id>/branches/<支路>.patch`）供查阅。

实现要点（2.2）：

- 配对规则：选了 `compare` 的并行之后必须有一个决定类型为 `pick` 的决策点，中间只能有活动；`pick` 决策点前面也必须有这样的并行。保存与可运行检查都按此校验（`_check_pick_pairs`）。编译时把并行标识与各路名称写到决策点上（`pick_from`、`pick_branches`），运行元数据 `workflow_nodes` 带出，供服务、运行页与飞书使用。
- 决定值不变：仍是 `approved` / `rejected`，对 `pick` 而言分别是「采用所选一路」与「都不采用」。所选支路随提交另传 `branch_choice`（REST、`submit_hitl`、飞书卡片回调），服务校验后写入 `branch_artifacts` 的保留键 `<并行>:__picked__`，不新增状态通道；决策记录多记一项 `picked`（支路名）。批准而未选支路时拒绝提交。
- 「都不采用」时各路改动全部留作补丁，工作区不变，按决策点的「不通过时」去向继续或结束。
- 合并选中支路时若与本轮工作区冲突，按并行合并冲突的方式升级；`pick` 决策点的路由发现待办是升级就停下，人选择「继续」后从该决策点之后继续。
- 运行页：待办带 `pick_options`，「关卡决定」下方出现「采用哪一路」；阅读区第一节是「两路对照」（`branch_comparison`）。飞书卡片每一路一个「采用「X」」按钮，另有「都不采用」。
- 编辑器：并行右栏顶部「汇合方式」（合并各路 / 对照择一）；决策点的决定类型增加「择一（两路对照）」，其「不通过时」改称「都不采用时」。

### 2.3 支路内决策点（第三步）

- 决策点通道改为按决策点标识记录：新增按键合并的 `gate_decisions`；`apply_gate_node` 与路由读自己的键，旧的单值通道保留给顺序流程兼容。
- 多条支路同时停在决策点时，待办按决策点逐个列出；全部给出决定后才恢复执行（LangGraph 同一超步中的中断一起恢复）。运行页与飞书卡片按决策点分别批复。
- 支路内决策点的「不通过时前往」只能指向同一支路内的节点或支路结束。
- 做完后，内置整网适配流程即可运行。

### 2.4 暂不支持

- 嵌套并行、支路内的系统节点与条件去向（`routes`/`next`）仍拒绝；目前没有需求，且会让汇合与恢复的语义复杂得多。

## 3. 取舍（已确认）

确认结果：择一用 **A**（人工决策点「择一」，需要时在其前面自行编排评审活动）；实施顺序按 **2.1 → 2.2 → 2.3**。以下保留当时列出的选项。

1. **两路对照由谁择一。**
   - A：人工决策点，新增决定类型「择一」，运行页与飞书列出各路摘要，人选一路（可附言）。
   - B：评审角色先写对照结论并推荐一路，再由人确认（A 之前加一个评审活动，流程里自行编排即可）。
   - C：完全由评审角色决定，不停下等人。
   建议 A，并允许在流程中自行在其前面加评审活动（等价于 B）。
2. **实施顺序。** 建议 2.1 → 2.2 → 2.3。若希望尽快让内置整网适配流程可运行，可先做 2.3；或作为过渡，把该流程的决策点挪出支路（改动内置流程文件，需确认）。
