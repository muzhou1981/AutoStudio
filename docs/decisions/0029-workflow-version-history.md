# 0029 · 流程版本记录与载入旧版

## 背景

1. 流程页保存即覆盖 `workflows/<id>/workflow.yaml`，改错后只能凭记忆改回。撤销与重做只在本页未离开时有效。
2. 自建流程不进 git（`.gitignore` 只保留内置流程），无法依赖仓库历史找回。
3. 已启动的运行使用当时的流程快照（`workflow_definition_ref`），因此版本记录只服务于编辑，不影响运行。

## 决定

1. **保存时记版本。** `save_workflow` 写入前，把这次保存后的内容记为 `workflows/<id>/versions/<序号>.yaml`，文件内是 `saved_at`（UTC，ISO 8601）与 `workflow`。重命名也走保存，同样记一版。
2. **首次记录先留原样。** 尚无版本时，先把保存前的内容（按校验后的形式，时间取文件修改时间）记为第 1 版，再记这次保存，避免启用本功能前的状态丢失。
3. **内容未变不新增。** 与最近一版相同时不记。最多保留 50 版，超出删除最旧的；序号只增不减。
4. **删除流程时一并删除。** 版本目录在流程目录内，随删除流程一起移除。内置流程不能保存，因此没有版本。
5. **改动摘要由服务端算。** `GET /api/workflows/{id}/versions` 由新到旧列出各版的保存时间、标题与相对前一版的改动：标题、说明、按节点标识比较的新增、删除、修改以及顺序调整。`GET /api/workflows/{id}/versions/{n}` 返回该版内容。
6. **回退即载入后保存。** 页面「载入到画布」把旧版作为未保存的修改放到画布上，可以运行检查、撤销，确认后按「保存」才生效，并记为新的一版。不提供直接覆盖的「恢复」接口，历史只追加不改写。

## 后果

- 每次保存多写一个文件，流程目录下多出 `versions/`；`list_workflows` 只读 `*/workflow.yaml`，不受影响。
- 改动摘要只到节点粒度，不展示字段级差异；需要细看时载入到画布查看。
- 回归测试：`tests/test_workflow_defs.py::test_saves_keep_versions_with_changes_and_skip_identical`。
