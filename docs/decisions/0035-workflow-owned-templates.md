# 0035 · 输出模板随流程保存

- 状态：已接受，已实现
- 关联：[0013](0013-custom-artifacts.md) 自定义产物与输出模板；[0002](0002-scenario-project-config-and-cropping.md) 内置产物模板的查找顺序不变；[ui-ux.md](../design/ui-ux.md) “输出的模板”一节已同步。

## 1. 背景

1. 流程编辑器给活动输出选择的本地模板，原先只在 `workflow.yaml` 里记下服务器上的绝对路径，文件本身不随流程保存。
2. 原文件被移动、删除或改写后，流程的运行前检查失败，或者下一轮按改过的内容执行；流程换一台机器或另一个账号，路径多半失效。
3. 版本记录只保存流程定义。回退到旧版本时，模板仍是当前磁盘上的内容。

## 2. 决定

1. **存放位置**：模板存放在 `workflows/<流程标识>/templates/`，流程里记 `templates/<文件名>`。只接受这一层的文件名，不含 `..`、子目录和以点开头的名字，不跟随符号链接。
2. **收入时机**：选文件时草稿里只记绝对路径；保存流程时，把外部绝对路径复制进流程目录并改记相对路径。已有流程里的绝对路径在下次保存时一并收入。保存时原文件读不到，就保留原路径，不拦截保存，由运行前检查指出。
3. **文件不可变**：文件名沿用原名；同名同内容时复用，同名不同内容时依次改用 `-2`、`-3`。已有文件一律不覆盖。
4. **界面内编辑**：右栏提供“查看”“编辑”“更换”。编辑后的正文随草稿以 `content` 字段提交，保存时另存为新文件，名字去掉末尾的 `-N` 后重新编号，例如 `spec.md`、`spec-2.md`、`spec-3.md`。内容未变时复用原文件。
5. **清理**：每次保存后，删掉既不被当前定义、也不被保留的历史版本引用的模板文件。
6. **解析**：运行前检查和编译时，相对路径按所属流程的目录解析；子流程按它自己的目录解析。开始一轮时，模板正文照旧存入快照，已开始的轮次不受之后的改动影响。
7. **限制**：本地模板须为 UTF-8 文本，不超过 256 KB，外部绝对路径同样适用。
8. **随附操作**：复制流程、存为子图时，用到的模板复制到新流程目录。导出 YAML 只带相对路径，界面提示模板文件不在导出内容里。
9. **统一的模板地址栏**：去掉“本地文件 / 链接”下拉框，只留一个编辑框和“选择文件”。类型按写法判断：`http://`、`https://` 开头是链接，以 `/` 或 `~` 开头的绝对路径和 `templates/<文件名>` 是本地文件，其他写法提示改正。YAML 仍写 `source`；省略时服务端按同一规则判断。已收入模板的“更换”换回空的编辑框，可以重新选择文件，也可以改填链接。
10. **接口**：新增 `GET /api/workflows/{id}/templates/check` 与 `GET /api/workflows/{id}/templates/content`。前者同时接受相对路径与绝对路径，后者只读本流程 `templates/` 下的文件。

## 3. 后果

- 流程目录自包含，模板不再依赖外部路径；版本回退时模板一并回到当时的内容。
- 外部原文件之后的改动不再影响流程，需要在编辑器里“更换”或“编辑”。
- 多次编辑会在 `templates/` 下留下 `-2`、`-3` 等文件，直到对应版本被清出保留范围。
- 直接在服务器上改 `templates/` 下的文件，等同于原地覆盖，引用它的历史版本随之变化；帮助页已注明。
- 这次不做从浏览器所在电脑上传模板，也不做两版模板正文的逐行对比；导出为含模板的压缩包留待以后。
