# 0021 · 一轮 Run 结束时回收 Agent、桥接与派生进程

- 状态：已实现
- 日期：2026-11-12
- 关联：[0020](0020-role-session-per-run-and-cursor-settings.md)（角色会话按 Run 复用）。

## 背景

1. **Agent 从不关闭。** Cursor 后端在进程内缓存 Agent，一轮结束后既不发送 `CloseAgent`，也不释放；全部 Run 共用一个桥接进程，直到服务退出。
2. **后台进程无人回收。** 智能体可用 Shell 启动后台命令。以真实 SDK 实测：`block_until_ms: 0` 的调用约 0.4 秒返回，进程随 Agent 保留；`nohup … &` 启动的进程自成会话、父进程变为 init，关闭 Agent 或退出 SDK 后仍然存活。开发服务、预览服务一旦这样启动，就会在 Run 结束后持续占用端口与内存。
3. Cursor SDK 的 `Bridge.launch` 不接受环境变量参数，但 Shell 工具继承桥接进程的环境。

## 决定

1. **每一轮一个桥接。** 绑定了 Run 的调用使用 `env GENI_STUDIO_RUN=<thread_id> cursor-sdk-bridge` 启动的专属桥接与客户端；未绑定 Run 的调用（模型列表、连通性校验）仍用 SDK 默认客户端。这一轮的 Agent 派生的所有进程，包括脱离会话的后台进程，都继承该变量。
2. **结束即回收。** 阶段变为已完成、已驳回或已停止时，`GraphRunService._done` 调用 `lifecycle.release_run`：关闭这一轮的 Agent、客户端与桥接，再扫描 `/proc/*/environ`，对本用户中带 `GENI_STUDIO_RUN=<thread_id>` 的进程先发 SIGTERM，2 秒后仍存活的发 SIGKILL。本服务进程及其祖先不在扫描范围内。删除一轮时同样回收。
3. **暂停、等待人工、中断时不回收。** 这些状态还会续跑，开发服务等进程保留；会话标识保存在磁盘上，续跑时重新启动桥接并续接 Agent。
4. **服务启停。** 启动时先从本进程环境中移除 `GENI_STUDIO_RUN`，以免由某一轮 Agent 启动的服务（例如自举预览）让默认桥接带上那一轮的标识；随后回收上一次服务的遗留：所属 Run 已结束的全部回收，未结束的只回收桥接（回调地址已失效），所属 Run 不在本服务中的不动。正常关闭时关闭全部桥接。
5. **Codex 后端暂不纳入。** 当前环境未安装 Codex SDK，无法核实其应用服务器是否支持传入环境变量；Codex 每次调用新建并关闭应用服务器，但其派生的后台进程仍不受回收。

## 后果

- 以真实 SDK 实测：一轮中 Agent 以 `nohup sleep 300 &` 启动的进程与该轮桥接的两个进程，在 `release_run` 后全部结束。
- 每个进行中的 Run 多一个桥接进程（Node），并行运行的轮次越多，常驻内存越高。
- 智能体若在命令中显式清空环境（`env -i`）启动进程，将逃出回收；这类情况只能靠智能体自律或人工清理。
- 依赖 Linux 的 `/proc`；在其他平台上只关闭 Agent 与桥接，不扫描派生进程。
