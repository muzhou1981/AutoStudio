# 0016 · 写锁按可写目录；并行写入的支路使用快照工作树

- 状态：已实现
- 日期：2026-11-11
- 关联：[问题与改进方案](../plans/architecture-remediation.md) D5；补充 [0006](0006-subgraph-parallel-and-reject-target.md) 的并行支路与 [0011](0011-run-executor-and-runtime-store.md) 的写锁等待。

## 背景

每轮已有独立工作树，但写锁以目标仓库为粒度（`.geni_studio/write.lock`），同一项目的多轮只能串行。并行支路中只要有写入或执行命令的角色就被拒绝编译运行，理由是「工作区未隔离」。

## 决定

1. **锁粒度。** `workspace_lock()` 按可写目录返回锁文件：独立工作树为 `<仓库>/.geni_studio/locks/<工作树名>.lock`，当前分支模式仍为 `<仓库>/.geni_studio/write.lock`。启动探测、执行时加锁与等待重试都使用同一个锁文件。删除运行与 `geni-studio gc` 一并回收锁文件。
2. **快照。** 分叉节点发现某条支路含写入或执行命令的角色时，用临时索引把本轮工作区当前内容（含未跟踪文件，遵守 `.gitignore`）写成快照提交，不改动本轮工作区的索引与分支。
3. **支路工作树。** 为这类支路在 `<仓库>/.geni_studio/branches/<运行标识>/<并行>__<支路>` 以快照提交建立分离头工作树，并安装推送防护。支路中的活动在该工作树执行（`use_worktree` 与状态中的 `workspace_path` 均指向它），只读支路仍读本轮工作区。
4. **汇合。** 汇合节点按支路顺序，把每条支路相对快照的差异以 `git apply --3way` 合并回本轮工作区，然后删除支路工作树。出现冲突时，冲突标记留在本轮工作区，本轮升级给人（`hitl_pending_kind=escalation`，说明列出支路与文件）。人处理后选择继续，从汇合节点之后执行；若下一步是关卡，停在关卡前等待决定。

## 后果

- 同一项目的多轮可以同时运行；并行支路可以包含程序员、测试等写入或执行命令的角色。
- 合并以文件差异为单位，不理解语义冲突；两路改动在不同文件中彼此矛盾时不会被识别，需要后续评审或测试发现。
- 合并后本轮工作区的索引被重置为 `HEAD`，改动保留在工作区中、处于未暂存状态。
