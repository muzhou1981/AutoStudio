# 0039 · 独立工作树的改动在批准后合并回开工分支

- 状态：已采纳
- 日期：2026-11-13

## 背景

除“自我改进”外，流程都在 `.geni_studio/worktrees/<Run 标识>` 的独立工作树与分支 `geni-studio/<Run 标识>` 上改代码（ADR 0007、0016）。一轮结束后既不提交也不合并，所选目录的当前分支上看不到任何代码。人用 Spec Kit 试跑时，以为代码丢失。同一轮还暴露出另一个问题：具备写文件能力的 Agent 把产物另存为仓库根目录下的 Markdown 文件，混进了代码改动。

## 决定

1. 开工时把工作区检出的分支写入 `.geni_studio/runs/<Run 标识>/land_branch.txt`。不写入运行状态，不改变 `base_branch` 对推送保护的含义。
2. 程序员的“提交入库”活动（`commits_on_branch: true`）按工作区分两种情况：当前分支模式沿用 ADR 0007；独立工作树模式先在本轮分支上提交除 `.geni_studio` 外的全部改动，再在所选目录中执行 `git merge --no-edit`，能快进时快进。不推送远端。
3. 以下情况拒绝合入并报错，改动保留在本轮分支：所选目录已切换到其他分支、有未提交的改动、有未完成的合并、合并冲突（先执行 `git merge --abort`，再列出冲突文件）。
4. 内置的 Spec Kit 与 NPU 算子开发（KDA）在最后一个决策点之后增加“提交入库”。
5. 所有活动的产出要求中写明：产物写在回复正文里，由工场保存到运行目录；不要在目标仓库中另建产物文件。

## 取舍

- 合入作为流程中的显式节点，而不是在一轮结束时隐式执行：泳道上能看到这一步；不需要合入的流程（例如只做分析的流程）不受影响。
- 没有改动隐藏的“通用软件开发”和 NPU 算子开发的三个子图；需要时由人复制流程后加上“提交入库”。
- 合入改动的是所选目录当前检出的分支。工场不先拉取远端，也不改写历史。
