# 0011 · 运行执行器与运行时库

- 状态：已实现
- 日期：2026-11-11
- 关联：[问题与改进方案](../plans/architecture-remediation.md) D4、C5、C6、C7、C9；补充 [0003](0003-pm-human-hitl-and-im-channels.md) 中 Web HITL 的提交语义。

## 背景

启动在 Web 进程内起守护线程；HITL 提交、继续、续跑与飞书回调在请求内同步调用 `graph.invoke`，一直跑到下一个关卡才返回，飞书回调还运行在 async 路由中，阻塞事件循环。停止、暂停请求只存在于进程内存，独立进程无法协作。状态接口在读取时写检查点（超时审计、中断标记），SSE 为同步生成器长期占用线程。运行列表与起名每次遍历全部检查点，图缓存与启动失败记录只增不减。

## 决定

1. **运行时库。** 与检查点同目录的 `runtime.sqlite`（`runtime/store.py`）：`run_jobs`（任务队列）、`run_controls`（停止与暂停请求）、`run_index`（运行索引）、`runtime_meta`（回填标记、最近一次飞书通知结果）。内存检查点（测试）对应进程内的内存库。
2. **入口只入队。** Web 与飞书入口在运行互斥锁内校验并写入人的决定，然后入队 `invoke` 任务（启动为 `start` 任务），立即返回当前状态。同一轮已有排队或执行中的任务时拒绝新的推进请求。命令行与基准测试仍可使用同步版本（`submit_hitl`、`resume`、`continue_interrupted`、`start`）。
3. **执行器。** `runtime/executor.py` 按入队顺序领取任务，同一轮串行；三种模式：
   - `inline`：入队后在当前线程执行（测试，`GENI_STUDIO_SYNC_START=1` 时默认）；
   - `thread`：随 Web 进程启动的线程池（默认，`GENI_STUDIO_EXECUTOR_WORKERS` 控制并发，默认 4）；
   - `external`：Web 只入队，由 `geni-studio-worker` 独立进程执行。
   任务因写锁被占（`WriteBusy`）时延后重试并显示「等待写锁」，不再记为启动失败；因请求仍持有运行互斥锁（`RunBusy`）时短暂延后。执行完成后刷新索引、发出事件，停在人工节点时由执行器发送一次飞书通知，结果写入运行时库供接口返回。
4. **跨进程控制。** 停止、暂停请求写入 `run_controls`；执行器领取任务前与每秒巡检时把请求同步到本进程正在执行的轮次。
5. **只读状态。** 状态读取不写检查点。阶段按执行情况推导：运行中但没有执行体时显示「中断」；有排队或执行中的任务时显示「运行中」；关卡超时说明由等待起点（`awaiting_since`，缺省时取检查点时间）推导。超时审计与中断标记由执行器每 30 秒的巡检写入。
6. **崩溃恢复。** 执行器启动与巡检时，把执行进程已退出（同主机且进程不存在）的执行中任务记为失败，对应轮次标记中断；启动任务失败的原因通过状态接口返回。
7. **运行索引。** 每次状态落定时更新 `run_index`；列表与起名查询索引，首次使用时从检查点回填一次。图缓存为容量 64 的最近最少使用缓存；启动失败不再单独存放于内存。
8. **SSE。** 改为异步生成器，按每轮的事件版本号变化推送，状态读取经线程池短调用，空闲时每 2 秒兜底刷新。

## 后果

- HITL 接口返回时阶段多为「运行中」，前端依赖 SSE 或轮询获得后续状态；响应中的 `job` 字段说明排队或等待写锁。
- 外部执行进程与 Web 进程须指向同一检查点目录；跨主机部署时崩溃判断保守地认为远端执行进程存活，需人工停止。
- `inline` 模式下若任务因写锁延后，任务会留在队列，直到有执行器运行；该模式只用于测试与本地调试。
