# 0005 · 所选流程编译为当轮的图

- 状态：已接受
- 日期：2026-11-07

## 背景

编排页可以把一份流程存成 `workflows/<id>/workflow.yaml`，项目也可以把它记入 `workflow.profile_id`。启动一轮时，LangGraph 仍固定执行 `src/auto_studio/workflows/default.py`。活动名称、角色和回退边不会成为当轮的节点，也不会进入 Cursor SDK。

[ADR 0001](0001-workflow-in-python-with-langgraph-studio.md) 把第一版定为 Python 图，并写明出现多套流程后再评估声明式格式。[ADR 0002](0002-scenario-project-config-and-cropping.md) 在 M2 不把 YAML 编译成另一张图，裁剪作用在同一张默认图上。编排页已经产生多套流程，这条限制不再覆盖「项目选中一份流程」的情形。

## 决策

1. 项目的 `workflow.profile_id` 指向一份已保存流程时，该次运行的 LangGraph 按 `workflows/<id>/workflow.yaml` 的节点编译。顺序、角色和回退边以该文件为准。
2. 未指定流程时，继续执行 `default.py`。`skip_nodes` 与 `features` 仍只裁剪这张默认图。
3. 活动节点按所属角色调用既有 `invoke_role`。系统提示仍是 `roles/<role>/role.md`。发给模型的是本活动要读的产物、要写的产物和活动名称，不是节点结构本身。模型正文写入该活动声明的产出产物。
4. 活动未单独声明产物时，采用该角色 `role.md` 的 `inputs` 与 `outputs`。要改写契约时，必须在节点上显式声明。
5. 决策点使用既有人工暂停与批复，不调用 Agent。决策点必须声明决定类型，才能接到现有的人工处理。
6. 回退边只能回到更早的节点。同一条回退单独计次，达到 `max_dev_retries` 后升级给人，不无限循环。
7. 启动和结束不调用 Agent，只标出一轮的两端。
8. 运行页展示当轮这张图上的节点。所选流程与默认图不混在同一条泳道里。
9. 活动缺少可解析的产物契约，或决策点缺少决定类型时，拒绝启动，并写明缺的是哪一项。

## 与既有决策的关系

- ADR 0001 继续有效的部分：运行时仍是 LangGraph，节点行为由 Python 实现，LangGraph Studio 调试的是编译之后的图。
- 本决策取代 ADR 0002「不做 YAML 全图编译」在已选择流程时的适用。未选择流程时，0002 的默认图与裁剪仍然有效。
- 角色之间仍通过产物协作。编译器不把只有名称的活动直接当成一条提示词。

## 后果

- 只保存或只在项目里选中流程，还不会改变运行。编译与启动接入之后，更换流程才会改变当轮节点。
- `default.py` 保留，作为未选流程时的实现。
- 现有只含标识、种类、名称、角色和回退目标的流程，在补上产物与决定类型之前不能执行。
