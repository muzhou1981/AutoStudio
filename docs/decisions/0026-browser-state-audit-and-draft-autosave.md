# 0026 · 浏览器侧状态清理：Run 草稿自动保存与主题入服务端

- 状态：已实现
- 日期：2026-11-12
- 关联：[0025](0025-role-model-params-and-menu.md)（角色模型参数记忆与服务端用户配置）。

## 背景

逐项排查页面中只存在浏览器的状态：

1. 项目、流程、角色与配置页的修改均经接口写入服务端，有未保存修改时离开会先确认。
2. 已启动的 Run 中，右栏的模型设置与 Skill 改动即时写入服务端。
3. 未启动的 Run（交付目标、Run 名称、附件清单、节点 Skill、角色模型与参数）只在页面内存中，须手动按「保存 Run 配置」；刷新、切换 Run 或新建时静默丢失，运行页没有离开确认。
4. `localStorage` 只余界面偏好：主题（`geni_studio_hitl_theme`）、左栏宽度、右栏宽度、人工待办区高度。角色模型参数记忆已在 ADR 0025 中迁到服务端。
5. 地址栏记当前项目、草稿、Run、节点、帮助章节与流程，用于导航和分享；访问令牌 Cookie 是凭据，不属于配置。

## 决定

1. **未启动的 Run 自动保存为草稿。** 选了项目且填过内容（交付目标、附件、改过的名称或任一设置）后，改动停笔约 1 秒经 `PUT /api/runs/drafts` 保存，草稿号由同一份表单的后续保存沿用。切换 Run、新建、复制、打开草稿前立即保存；关页时以 `keepalive` 发出。设置存在组合不受支持等问题时不自动保存，避免存入启动时会被拒绝的配置。手动按钮保留，作立即保存。
2. **保存排队。** 所有草稿保存依次发出，不并发，首次保存返回草稿号前的后续改动不会另建草稿。表单换成另一份 Run 后，旧表单的在途保存仍按旧草稿号写完，但不再改动页面。启动 Run 与删除当前草稿前，丢弃尚未发出的改动并等待在途保存返回，使草稿号确定，删除后不会被重新写出。
3. **主题入服务端用户配置。** `user_config.json` 增加 `ui.theme`（`light` 或 `dark`，空值回到系统设置），接口为 `GET`/`PUT /api/config/user/ui`。浏览器里的同名键改作首屏缓存，避免读取返回前闪现另一种主题；服务端尚无主题而本浏览器切换过时，首次读取把本地选择补写上去。
4. **面板尺寸留在浏览器。** 左栏、右栏宽度与人工待办区高度取决于屏幕尺寸，按机器分别保存更合适，不入服务端。

## 后果

- 新建 Run 填写到一半刷新或切走，内容会保存在 Run 列表的草稿中；只打开页面、未填写内容时不产生草稿。
- 新建 Run 表单沿用上一份表单的交付目标文字（原有行为），此时再改动会另存为一份新草稿。
- 运行页仍无离开确认：自动保存后不再需要。
