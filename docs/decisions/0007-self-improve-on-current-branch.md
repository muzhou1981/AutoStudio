# 0007 · 自我改进直接在当前分支上改

- 状态：已接受
- 日期：2026-11-09

## 背景

自我改进原先把改动留在 `.geni_studio/worktrees/<thread_id>`，不合并回当前分支。这样一轮结束时，人批准了「确认入库」，代码仍不在开工时检出的分支上。配置管理员的职责是模板、规范和仓库级基线，不是替程序员提交这一轮的代码。

## 决策

1. 自我改进（`workflows/self_improve/workflow.yaml` 的 `workspace: current_branch`）不另建 git 工作树。角色直接修改目标仓库当前检出的分支。
2. 开工时允许工作区已有未提交改动；自我改进会在同一分支上继续修改，确认入库时由程序员节点一并提交。若处于分离头指针，仍拒绝启动。
3. 确认入库之前，活动不得执行 `git commit` 或 `git push`。
4. 人类确认入库之后，下一格「提交入库」由程序员执行：只在开工时的那个分支上提交尚未提交的改动。分支若已切换，拒绝提交。不推送远端。
5. 配置管理员在程序员提交之后登记交付基线。配置管理员不执行这次开发提交。
6. 其他流程仍使用独立工作树。本决策不改变通用软件开发的隔离方式。

## 后果

- 自我改进会改写目标仓库当前分支上的文件。目标是工厂仓库时，仍须显式设置 `GENI_STUDIO_ALLOW_FACTORY_TARGET=1`。
- 「提交入库」由引擎执行 git 提交，不调用模型。当前分支已在目标仓库检出，不能再放到另一份工作树里提交。
