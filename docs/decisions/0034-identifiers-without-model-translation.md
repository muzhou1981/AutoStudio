# 0034 · 生成标识不再调用模型翻译

- 状态：已接受，已实现
- 关联：延续 [0027](0027-workflow-editor-loops-and-menus.md) 第 6 条“复制不调用模型”；[ui-ux.md](../design/ui-ux.md) 中项目、流程、角色的标识规则已同步改写。

## 1. 背景

1. 新建项目、流程、角色时，标识按标题生成。标题含中文时，服务端先通过当前 Agent 后端把标题译成英文，再整理成标识。
2. 翻译走的是一次完整的 Agent 调用。在 Cursor 后端实测：“前端缺陷修复”耗时 18.6 秒，“测速流程”耗时 76 秒。按下“创建”后，页面在这段时间里没有任何进展。
3. 创建请求本身（写文件、读列表）合计约 200 毫秒，等待几乎全部来自翻译。

## 2. 决定

1. 生成标识不调用模型。名称本身符合标识规则时原样保留；英文名称整理成小写并用 `-` 连接；名称含中文，或整理后为空时，使用 `project-1`、`workflow-1`、`role-1` 这类序号。重名时加 `-2`、`-3`。
2. `allocate_identifier` 去掉 `translate` 参数，删除 `backend_translate`。项目、流程、角色与“按目录创建项目”共用同一规则。
3. 已有标识不受影响。标识创建后仍不可修改。

## 3. 后果

- 新建项目、流程、角色在百毫秒级完成，不再依赖后端可用、网络与模型额度。
- 中文标题得到的标识不再表达含义，例如“前端缺陷修复”得到 `workflow-3`。标题仍是界面上的主要名称，标识只出现在地址栏、文件目录和右栏说明里。
- 需要有意义的标识时，可以先用英文标题创建，再把标题改成中文；标识保持不变。
