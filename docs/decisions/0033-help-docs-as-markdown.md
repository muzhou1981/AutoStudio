# 0033 · 帮助正文改为仓库内的 Markdown 文档

- 状态：已接受，已实现
- 关联：取代 [ui-ux.md](../design/ui-ux.md) §8.1 原先「正文按条目写在页面里」的约定；§8.1 已同步改写。

## 1. 背景

1. 帮助正文直接写在 `hitl.html` 里，十一篇全是平铺的条目列表，没有小节、编号步骤、表格或截图。第一次使用的人找不到一条从安装到走通一轮的路径；查某个细节时，要把整篇从头读到尾。
2. 每加一项功能就往对应一篇末尾追加一条，篇内顺序随上线先后而定。「流程」一篇积累了 18 条，编辑操作、节点类型、校验规则和快捷键混在一起。
3. 文案与代码脱节：「驳回则这一轮结束」在决策点可以设「不通过时」的去向后已经不对；配置页早已没有「默认工作区」字段，帮助仍在介绍它。
4. 改一句帮助要改页面 HTML，评审时与界面代码混在同一份差异里，非开发人员难以参与。

## 2. 决定

### 2.1 正文来源

- 正文写在 `docs/help/<篇>.md`，配图放在 `docs/help/images/`。仓库里直接阅读也能看懂。
- 服务端渲染帮助所需的 Markdown 子集（`geni_studio.web.help_docs`）：二、三级标题与 `{#id}` 锚点、段落、有序与无序列表（列表项下可再缩进一层）、表格、代码块、单独成行的图片、`> [!NOTE]`／`[!TIP]`／`[!WARNING]` 提示框、以 `<` 开头的原样 HTML 块，以及行内粗体、代码、链接和 `<kbd>`。超出子集的写法在渲染时报错，并由测试拦截。
- 不引入第三方 Markdown 库。正在运行的主服务不会因新依赖而在下次重启时缺包；子集足够帮助使用，规则也更容易约束。
- 正文由人维护并随仓库评审，原样 HTML 块不做清洗。只用于架构图这类需要随主题变色的图示。
- `GET /api/help` 每次读取文件，改完刷新页面即可看到；`GET /api/help/assets/<文件名>` 只接受 `images/` 下的小写文件名。

### 2.2 结构

- 九篇，分三组：入门（快速入门、核心概念）、使用手册（项目、运行、流程、角色、配置）、参考（常见问题、架构）。
- 「概览」与「入门指南」合并为「快速入门」，用不调用外部模型的 stub 后端走通一轮，每一步写操作与预期结果。
- 「Agent」「工作区」「飞书」「环境」合并为「配置」一篇的四节；旧地址按别名转到新地址。
- 架构移到最后，标明面向管理员。

### 2.3 查找

- 右栏改为搜索、本页目录和「打开某页」入口，不再只写「帮助只读。」
- 搜索在浏览器内按小节匹配全部篇目，不需要服务端索引。
- 运行、流程、角色、项目和配置页的关键标题旁放「?」，在新标签页打开对应小节，避免打断正在编辑的内容。

## 3. 影响

- 二、三级标题的 `{#id}` 成为对外地址的一部分。`tests/test_help_docs.py` 检查篇目与左栏菜单一致、篇间链接与界面「?」指向存在的小节、配图存在。
- 帮助首图从 `src/geni_studio/web/static/` 移到 `docs/help/images/overview.jpg`，README 的引用随之更新。
- 运行页决策点的选择框标签由「关卡决定」改为「决定」，与帮助统一使用「决策点」一词。
- 截图会随界面改版而过时。界面有明显变化时，用预览实例重新截取，并保持文件名不变。
