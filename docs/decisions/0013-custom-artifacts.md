# 0013 · 流程自定义产物、产物落盘与引用

- 状态：已实现
- 日期：2026-11-11
- 关联：[问题与改进方案](../plans/architecture-remediation.md) D3、D2（产物引用与全文传递）；补充 [0005](0005-selected-workflow-compiles-run-graph.md) 的产物契约。

## 背景

编译器拒绝不在 `FactoryState.__annotations__` 中的产物名。NPU 算子、整网适配等场景需要 `kernel_spec`、`perf_report` 一类专用产物，每新增一种都要改 Python 状态定义，与「流程由配置描述」的目标相悖。

## 决定

1. `FactoryState` 增加合并式字段 `extra_artifacts: dict[str, str]`。图状态已有字段的产物仍写原字段，其余产物写入 `extra_artifacts[<名称>]`；读写统一经 `workflows/artifacts.py` 的 `read()` 与 `put()`。
2. 自定义产物名须满足 `^[a-z][a-z0-9_]{0,63}$`。编译时额外检查：任何活动读取的自定义产物，必须由流程中某个活动产出；否则拒绝编译。
3. 产物落盘（`persist_values`）把自定义产物写到运行目录 `<名称>.md`；产物查看接口接受本轮 `extra_artifacts` 中存在的名称；状态接口把自定义产物展开到 `values` 顶层（与已有字段同名时以已有字段为准），前端无需区分两类产物。

4. **产物登记。** 编译图中的每个节点返回后，登记其产出的产物到合并式字段 `artifact_meta[<名称>]`：产出节点、第几次产出、`sha256`、字数，以及有运行目录时的落盘路径 `.geni_studio/runs/<thread_id>/artifacts/<名称>.md`。人类需求、关卡日志与审计记录不登记。运行结束时的 `persist_values` 同样写入 `artifacts/`，`manifest.json` 附带登记表；读取时先找 `artifacts/`，再找旧位置。
5. **提示词引用。** 上游产物经 `artifacts.reference()` 写入提示词：后端声明 `read_files` 能力、登记的哈希与当前正文一致且文件存在时，给出路径、字数、哈希前 12 位与产出节点，要求先读全文；否则（包括 Stub 后端与并行支路的局部产物）内联全文。提示词构造不再按字符截断，流程模板也整份内联。

## 后果

- 新增产物只需在流程定义中声明，无需修改代码。
- 默认图的固定节点仍只认识已有字段；自定义产物只在编译流程中流转。
- 自定义产物不参与默认图的结论判定与变更控制；若某个自定义产物需要成为判定依据，须在流程中以结论块产出。
- 提示词长度不再受截断保护；内联全文的场景（Stub、无运行目录）会随产物增长，真实后端则只增加一行引用。
