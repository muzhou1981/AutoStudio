# 0040 · 项目概览与“代码尚未回到项目目录”的判断

- 状态：已采纳
- 日期：2026-11-13

## 背景

项目页右栏原来只写所选流程的名称，看不出这个项目的代码落在哪里、最近跑过哪些 Run。人修改项目的工作区后，原工作区里的 Run 仍按开工时记录的路径续跑与入库（ADR 0039），新的 Run 才在新目录开始；页面对此没有任何提示，人容易以为改动随工作区一起迁走了。删除项目时，也需要知道哪些 Run 还没结束。

## 决定

1. 新增 `GET /api/config/projects/<标识>/overview`，返回所选流程（标题、是否存在、是否直接改当前分支）、按项目配置解析出的工作区及其当前分支、最近 5 轮 Run、Run 总数与未结束轮数，以及代码尚未回到项目目录的 Run（未结束的 Run 一并列入，原因写“未结束”）。
2. “未结束”指阶段为运行中、等待人工、已暂停或已中断。删除项目时，存在未结束的 Run 则返回 409 并列出名称。
3. 已结束的 Run 在下列任一情况下视为“代码尚未回到项目目录”，按顺序判断，只取第一条原因：
   - 工作树 `.geni_studio/worktrees/<Run 标识>` 仍在，且 `git status --porcelain` 非空：“工作树里有未提交的改动”。
   - 分支 `geni-studio/<Run 标识>` 存在，且相对仓库当前检出的分支有提交未合入：“本轮分支有 N 个提交未合入 <分支>”。
   当前分支模式的 Run 没有工作树与本轮分支，不会出现在这份名单里。
4. 只检查最近 50 轮，避免项目 Run 很多时拖慢页面。
5. 修改工作区时，表单在工作区下方列出名单与原因，按“保存”时再确认一次；右栏只列已结束的那部分，未结束的已在 Run 小节里计数。

## 取舍

- 判断依据是仓库里的工作树与分支，而不是运行状态里的记录：人可能手动合并或删除过分支，以仓库现状为准。
- 只对项目当前配置的工作区判断。更早之前换过的工作区不再追溯。
- 不阻止修改工作区：换目录是合理操作，只需让人知道旧改动留在原处。
